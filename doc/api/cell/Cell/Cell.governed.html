Synthesizes a fully managed Cell instance with explicit control over its Identity Lifecycle, Administrative Policy, and Atomic Isolation.

This factory serves as the primary Administrative Enforcement Point for nodes requiring strict security and compliance. It allows for the creation of a dedicated security perimeter, ensuring that every state transition is validated against a formal Capability-Based Access Control (CBAC) manifest.

When to use

Only when you need fine‑grained governance: TTL, specific authority tiers, or atomic locking. For typical application state, prefer the simpler Cell.state or Cell.ingress.

How it works

All parameters are mandatory (no defaults). You must explicitly supply a context – there is no system fallback. This ensures every governed node has a defined security posture.

Non‑obvious

Governed cells participate in a mutual authorization handshake: both the pulse and the receptor scrutinise each other's context before data is exchanged. If either side fails the check, the pulse is neutralised.

Parameters:

  • ephemeralPolicy: Resource Management. Defines the TTL or invalidation triggers for the node.
  • bind: Ingress Link. The primary dependency for reactive flow.
  • context: Administrative Context. The metadata registry defining Authority Tier, Clearance, and Sensitivity.
  • receptor: Transformation Pipeline. The logic defining how the cell synthesizes incoming stimuli.
  • testRule: Integrity Gate. The TestCell used to authorize state changes. Defaults to TestCell.allowAll.
  • synapses: Egress Network. Configures signal routing and distribution behavior.
  • forceLock: Atomic Isolation. If true, establishes a dedicated synchronization domain for the node.

Returns:

A fully managed Cell instance with a dedicated policy perimeter and explicit lifecycle configuration.
