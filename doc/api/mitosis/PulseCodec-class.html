PulseCodec

PulseCodec class

Canonical serialiser for Pulse.

How it works

toJson encodes the payload, type, priority, timestamp, source (by cell id), trace, PulseContext lineage, and a parent digest. The parent is not recursively serialised — only the digest of its own canonical form — because deep chains would balloon the wire format, and because identical parent pulses should collapse to identical hashes (that is what makes replay reconstructable from the ledger). fromJson is the inverse: it verifies the parent digest and rebuilds the chain bottom-up, root first.

Non-obvious: the materialise boundary

The hot path produces _FastPulse/_StepPulse flyweights. Those carry their state in plain fields instead of the canonical record, so toJson rejects them by default and materialise is the explicit boundary that replaces them with equivalent plain _Pulse nodes. Always encode PulseCodec.toJson(PulseCodec.materialise(pulse)).

See also:

  • PulseContextCodec — the context codec this serialiser delegates to.
  • fingerprint — the hashing primitive the parent digests use.
