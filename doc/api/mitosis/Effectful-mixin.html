Effectful

Effectful mixin

The declarative marker for effectful receptors and rules.

How it works

Mixing in Effectful does not automatically route effects through a journal — the receptor body must call journal.clock(), journal.io(...), etc. explicitly. What the mixin provides is:

  1. A compiler-enforced contract at the retrofit sites. The journal changes asyncMap and friends to accept a non-optional journal: parameter, and the Effectful mixin is how the framework signatures communicate "this receptor must be journalled".

  2. A stable purity override. Any class mixing in Effectful reports Purity.effectful from Receptor.purity and TestCell.purity. The CellGraph uses this in the engine to refuse an exact (journal-free) replay of a cell whose purity is effectful — so a user who forgets to journal gets a loud failure at graph construction, not a silent divergence during replay.

Non-obvious: this is not a base class

Effectful is a mixin, not a class, so receptors can extend their existing hierarchy (e.g. _Receptor in receptor.dart) without multiple inheritance. The mixin's only member is Purity get purity => Purity.effectful, which the retrofit sites already declare on their own classes — the mixin exists so user receptors can opt in without writing the override by hand.

See also:

  • EffectfulReadOnly — the read-only variant.
  • Purity — the classification this marker reports.
