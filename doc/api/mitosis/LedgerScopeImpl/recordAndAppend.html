Queues a coordinated append. The deltas are snapshotted now (the current pulse's captured set) and the append runs on the scope's serialisation chain, so many synchronous ValueCell.updates inside one scope produce entries in the exact update order with the exact delta attribution. effects are the explicitly captured effects; any cooperatively captured _pendingEffects are appended to them.

Non-obvious: identity dedup is load-bearing

On the immediate (apply/update) path, a cooperative capture (e.g. TestCellReplay's verdict sweep) stores the same record instances that the journal-watermark sweep in recordPulse already collected. Concatenating both lists would store every such effect twice, and the replay journal would report one unused effect. EffectRecord does not override ==, so a set dedupes by identity — exactly the "same record captured twice" case, and nothing else.

Future<void> recordAndAppend({
  required Pulse pulse,
  required ApplyReceipt receipt,
  required String cellId,
  required List<EffectRecord> effects,
  List<StateDelta>? deltas,
}) {
  final deltaList = deltas ?? List<StateDelta>.from(_pending);
  if (deltas == null) _pending.clear();
  final extraEffects = List<EffectRecord>.of(_pendingEffects);
  _pendingEffects.clear();
  final allEffects = <EffectRecord>{...effects, ...extraEffects}.toList(
    growable: false,
  );
  final task = _tail.then(
    (_) => ledger.appendInternal(
      pulse: pulse,
      receipt: receipt,
      cellId: cellId,
      effects: allEffects,
      deltas: deltaList,
    ),
  );
  // Keep the chain alive after a failed append; the failure is still
  // reported to the caller of this method.
  _tail = task.catchError((_) {});
  return task;
}
