Synapses

Synapses<P extends Pulse, L extends Cell> class abstract interface

The distribution registry for a Cell's downstream observers — where a pulse goes after a cell accepts it.

Where to start

  • Synapses.enabled — the default; an empty, live registry ready to accept links. Cells created via Cell.value/Cell.observe/etc. already use this unless you override it.
  • Synapses.disabled — for terminal/sink cells that should never broadcast (e.g. what Cell.observe uses internally, since an observer is a dead end by design).
  • Synapses(downstreams: [...]) — construct with an initial set of observers, or add filter: to redact/transform outgoing pulses before they're delivered.

You'll set this via a synapses: parameter on a Cell.* factory far more often than you'll construct one directly.

How it works

Synapses manage a list of downstream cells. When a pulse is broadcast, it's filtered (if a FilterRule is set) and then delivered to each observer in sequence. The framework ensures cycle safety by tracking visited nodes.

Non‑obvious: propagation strategies

By default, delivery is synchronous and immediate. PropagationPolicy lets you switch to async, debounced, throttled, batched, and several other strategies — worth knowing this exists before you reach for a manual Timer or Stream.debounce around a cell yourself.

Non‑obvious: cycle safety

If cell A's synapses eventually loop back to A, the framework won't hang — each pulse carries its own visited-node record, so a cycle is silently broken rather than causing infinite propagation. You don't need to guard against this yourself when wiring cells together.

Example: simple distribution

final synapses = Synapses<String, Cell>(
  downstreams: [logger, analytics, uiUpdater],
);

See also: FilterRule (transform/redact outgoing pulses), Synapses.link / Synapses.unlink (the usual way to add/remove observers at runtime, rather than calling link/unlink on this directly).
