Initializes the primary ReceptorBase, the foundational engine for Pulse Transformation and state governance within a Cell.

This constructor assembles a multi-stage processing pipeline—comprising optional preProcess, rule, and postProcess stages—that defines how a node reacts to incoming stimuli. It serves as the architectural gateway between the Synapses (the distribution network) and the Cell's internal state logic.

1. Architectural Role: The Logic Interface

The ReceptorBase acts as the Validation and Transformation Layer. Its primary purpose is to govern Incoming Propagation—the process of receiving, validating, and applying signals to the state. By decoupling the cell's identity from its behavioral logic, this constructor allows for the injection of specialized rules that dictate how the cell responds to external data changes.

2. The Transformation Pipeline:

When this receptor is invoked (via call), it executes a strict, hierarchical sequence:

  1. Input Gating (preProcess): If provided, this PulseRule acts as a "Global Guard" or "Sanitizer." It runs before core logic. If it returns null, the receptor terminates propagation, protecting the cell from invalid or irrelevant stimuli.
  2. Core Reaction (rule or reaction): The primary logic executes here. This is where the stimulus is mapped to the cell's specific value type. This stage is wrapped in a protective error boundary to ensure that logic failures do not destabilize the reactive graph.
  3. Commitment Logic (postProcess): The final stage before downstream notification. This handles the persistence of the transformed value into the storage layer and performs final integrity checks.
  4. Emission: If the pulse survives all stages, it is automatically pushed through the cell's Synapses to notify downstream observers.

3. Flyweight Strategy: Record Packaging

To maintain a lean memory footprint, this constructor utilizes a Flyweight Strategy via a bitmask Record. The internal storage shape is determined at compile-time based on which rules are provided.

Parameters:

  • rule: The primary PulseRule defining the core transformation logic.
  • preProcess: An optional PulseRule for early-stage filtering, security gating, or input normalization.
  • postProcess: An optional PulseRule for late-stage persistence and commitment.
  • reaction: Functional Transformation. An optional mapper providing a simplified interface for basic reactions when a full PulseRule is not required.
  • user: Contextual Metadata. An optional dynamic payload (Record) carrying configuration data that specialized receptors use to adjust their behavior.
