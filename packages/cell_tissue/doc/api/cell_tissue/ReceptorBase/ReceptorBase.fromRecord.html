A base constructor that initializes the ReceptorBase from a pre-compiled Record of configuration properties.

This constructor serves as the foundational initialization point for the entire receptor hierarchy. By utilizing Dart's positional and named Record fields, it allows for a highly memory-efficient way to store optional transformation logic, validation rules, and metadata without the overhead of maintaining multiple individual fields in the class structure.

Purpose:

The primary purpose of this constructor is to facilitate Property Resolution Efficiency. In a large-scale reactive graph, thousands of receptors may be instantiated. Storing their operational configuration (such as transformation functions or global filters) in a single Record allows the framework to resolve these values using optimized access patterns, while ensuring the receptor remains a compile-time constant (const).

Architectural Role:

  • Configuration Storage: It acts as the final destination for operational data gathered by higher-level factory constructors. This decouples the public API of the receptor from its internal storage mechanism.
  • Immutability Guarantee: By accepting a Record, it ensures that once a receptor's strategy is defined at construction, it cannot be evolved at runtime. This preserves the deterministic nature of the reactive pulse chain, which is critical for debugging and state consistency.
  • Extensibility: It provides a unified hook for specialized subclasses (like those for collections) to pass varying sets of parameters—such as interceptors, master rules, or security context—in a format that integrates seamlessly with the framework's property resolution system.

Memory & Performance Optimization:

Using a Record-based initialization significantly reduces the memory footprint of each receptor. In standard class architectures, every instance allocates space for every field, even if they are null. This constructor allows the instance to only "carry" the properties that were actually provided, which is vital when composing deep chains of receptors and synapses.

Logic Flow:

  1. A public constructor (e.g., ReceptorBase.new or a factory) assembles the relevant rules and metadata into a Record.
  2. This constructor receives that Record and anchors it to the instance.
  3. During a pulse broadcast (via call), the receptor resolves the necessary functions from this configuration bundle to execute the transformation pipeline.

Parameters:

  • record: A Record containing the operational configuration of the receptor. This typically includes the primary transformation logic, pre-processing rules, and any associated user metadata.
