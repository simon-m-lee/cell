Creates a PulseRuleChain that combines multiple rules into a single unit.

When to use

Use this when you need to apply a series of transformations in order. It's the typical way to build multi‑stage processing pipelines.

How it works

By default, rules are executed sequentially in the order provided. The output of one rule becomes the input of the next. You can optionally provide a custom strategy function to override the default execution logic.

Non‑obvious

  • If any rule returns null, the chain short‑circuits and returns null immediately.
  • The chain handles both synchronous and asynchronous rules automatically.
  • Errors in individual rules are caught and the chain continues with the last known good pulse, ensuring resilience.

Example: pipeline with conditional logic

final pipeline = PulseRule.chain(
  [rule1, rule2, rule3],
  strategy: ({required cell, required pulse, user}) {
    // Custom logic: skip rule2 if pulse is null
    if (pulse.payload == null) {
      return rule3.call(cell: cell, pulse: pulse);
    }
    return rule1.call(cell: cell, pulse: pulse)
        .then((r) => r != null ? rule2.call(cell: cell, pulse: r) : null)
        .then((r) => r != null ? rule3.call(cell: cell, pulse: r) : null);
  },
);

Parameters:

  • rules: An ordered collection of PulseRules to be orchestrated.
  • user: Optional context metadata passed to the strategy.
  • strategy: An optional override function that dictates how the rules are applied to the incoming _pulse.
