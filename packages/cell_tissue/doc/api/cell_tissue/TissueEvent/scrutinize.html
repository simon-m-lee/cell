Scrutinizes the Receptor to determine if it possesses the necessary Context and isGoverned status to process this pulse.

When to use

You rarely call this directly – the framework uses it internally during the Inverted Gate handshake. It's the mechanism that lets a pulse challenge a receptor before revealing its payload.

How it works

The receptor must "submit" itself to the pulse. The pulse then examines the receptor's host cell, its governed status, and its context. If the receptor passes scrutiny, the pulse unlocks and returns its kernel (payload). If not, it returns null – the signal is neutralised.

Non‑obvious

This is a reciprocal handshake – both the pulse and the receptor validate each other. It's not a one‑way permission check.

Parameters:

  • receptor: The entity requesting access to the pulse's internal state.
  • positionalArguments: Contextual data provided by the Receptor to satisfy the pulse's scrutiny logic.
  • namedArguments: Additional named parameters for the handshake.

Returns:

The internal kernel if authorized; null if neutralised.
