PulseBase

PulseBase<P> class abstract

The foundational implementation of the Pulse interface, providing the core logic for signal storage and property resolution.

PulseBase serves as the Standard Signal Template. It handles the internal complexities of the Pulse interface, including bitmask record management, causal chain resolution, and support for composite "Signal Bundles."

1. Architectural Role: The Structural Backbone

This class is the engine behind the pulse's immutability and memory efficiency. It utilizes a Flyweight Pattern via the internal _record, which ensures that a pulse only consumes memory for the specific metadata attributes it explicitly carries, rather than a full object footprint for every node in the distribution network.

2. Causal Chain Resolution (Inheritance Mapping)

PulseBase implements the framework's Property Inheritance Resolution. Many properties (like context, source, or onComplete hooks) are not duplicated across evolved signals. Instead, the base class "walks up" the _parent chain until it finds the original source value, ensuring that a signal always maintains its logical connection to the root.

3. Signal Composition

By mixing in IterableMixin, PulseBase allows pulses to behave as Composite Bundles:

  • Atomic Pulse: A standard stimulus representing one instruction.
  • Composite Pulse: A collection of multiple pulses (possibly of disparate types) traveling together, allowing Receptors to process multi-faceted signals in a single synchronized wave.

4. Reactive Lifecycle Support

It provides the infrastructure for the onComplete, onError, and onProgress lifecycle hooks. These allow the reactive wave to communicate its status back to the IngressHandle or external observers once it has finished its journey and been fully integrated into the state graph.
