Indicates whether this Provenance Dimension is a structural invariant or a dynamic operational attribute.

In the framework's Blueprint Synthesis model, the evolvable flag determines the "rigidity" of a signal's metadata during a PulseContext.evolve operation. It separates the pulse's immutable identity from its mutable mission.

1. Static Pillars (evolvable: false)

Dimensions marked as non‑evolvable are structural invariants. They constitute the Causal Trace and must be inherited exactly from the source. Any attempt to modify these via evolve is ignored.

2. Fluid Boundaries (evolvable: true)

Dimensions marked as evolvable represent the Operational Intent. These can be refined as a pulse propagates through different cells.

3. Architectural Role: Mutual Authorization and Invariant Enforcement

During validation, a receptor evaluates this flag to enforce Capability‑Based Access Control (CBAC).

Developer Ergonomics

This is a low‑level governance property. Human developers interact with the pre‑configured Provenance enum values and do not need to manage this flag manually.
