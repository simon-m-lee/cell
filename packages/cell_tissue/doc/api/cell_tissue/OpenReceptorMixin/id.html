id

id property

String get id
inherited

A stable, serialisable identifier for this cell handle.

Unlike hashCode — which is derived from the root principal's identityHashCode and is therefore process-local — id is intended to survive persistence. The codec uses it to reconstruct a pulse's source after a snapshot is loaded; CellGraph uses it as the registration key.

Guarantees

  • Stable within a process. Two calls to cell.id return the same string.
  • Stable across processes for registered cells. A cell registered with a CellGraph returns the graph-assigned name.
  • Stable across processes for unregistered cells, too. The fallback is nucleus:<hex(identityHashCode(rootNucleus))>, which is stable within a process and only cross-process-stable once graph registration lands. This is documented so consumers do not assume cross-process identity without a registered graph.

Non-obvious: id ≠ hashCode

hashCode is a set-membership key — a deputy and its principal must hash equal (they do), and ValueCell cannot change its hash when it evolves. id is a wire identity — a deputy and its principal may share the same id (they walk to the same root) but graph registration gives them distinct registered names. Do not substitute one for the other; they answer different questions.
