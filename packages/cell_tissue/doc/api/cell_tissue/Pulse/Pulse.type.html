Creates a categorized Signal with a specific name or label.

Where to start

Use this when you want to label a Pulse so the system knows what "kind" of message it is without having to open and read the data inside.

When to use

  • Labeling Actions: To mark a signal as an "alert," "update," or "request."
  • Smart Routing: When you want certain Cells to only listen for specific types of messages.
  • Clear History: To make the Audit Trail easier to read by labeling why a change happened (e.g., "manual_override" vs "auto_sync").

How it works

The type acts like a label on the outside of an envelope. When the signal moves through the Switching Fabric, the system can quickly look at the label and decide where it should go or if it has permission to pass through a Security Gate.

Example

// Label the signal so the system knows it's a security alert final alert = Pulse.type('security_alert', payload: 'Door Unlocked');


* [type]: **Routing Tag.** A unique identifier used to route,
  group, or filter signals within the reactive graph.
* [payload]: The primary data or instruction carried by the pulse.
* [priority]: **Scheduling Priority.** Defines the dispatch urgency
  within the framework's priority queues during the **Egress Phase**.

### Returns:
A categorized [Pulse] instance ready for type-aware propagation through
the reactive network.
