Creates a Collective Pulse by aggregating multiple signals into a single, atomic wave.

A Collective Pulse is a Signal Bundle that allows multiple independent pulses to travel together as one unit. This is essential for batch operations, coordinated updates, or any scenario where multiple state changes must be processed atomically.

Where to start

Use this when you need to send multiple related signals as a single atomic unit. For simple two-pulse combinations, the + operator is more concise: pulseA + pulseB.

When to use

  • A batch update that must be processed together.
  • Coordinating multiple state changes that depend on each other.
  • Reducing overhead by combining several small pulses into one wave.
  • When you want to iterate over a collection of pulses as a single entity.
  • When you need to apply common metadata (context, type, priority) to a collection of pulses.

How it works

  • The factory takes an iterable of pulses and bundles them into a single Collective Pulse.
  • The collective's payload is the iterable of pulses itself – this is the collection you provided.
  • The collective is iterable – you can loop over it to access each individual pulse.
  • The collective is processed atomically – all sub‑pulses travel together through the graph.
  • You can override the context, type, source, and priority by passing them as named parameters to this constructor.
  • The collective's isComposite property returns true.
  • Each sub‑pulse retains its independent identity, causal trace, and parent chain.

Non‑obvious

  • A Collective Pulse is not the same as an EvolvedPulse created by the + operator. While both are composites, Pulse.batch() creates a collective where the payload is the collection of pulses, whereas + creates a chain that preserves parent-child relationships.
  • The collective does not create a new causal chain; it simply groups existing pulses for atomic propagation.
  • If you need to add a step to all pulses in a collective, you can iterate over the collective and call withStep on each, then create a new collective from the processed pulses.
  • The + operator is syntactic sugar for creating a CollectivePulse chain, not a Collective Pulse: pulseA + pulseB creates a chain where pulseB is a child of pulseA, while Pulse.batch([pulseA, pulseB]) creates a collective where both pulses are independent members and the payload is the collection [pulseA, pulseB].
  • The collective's payload is the entire iterable of pulses, not just the first pulse's payload. This means collective.payload is the collection itself.
  • The collective's source is the source of the first pulse, unless overridden via the source parameter.
  • The collective does not have its own parent – the parent chain of the collective is null (it's a root collective). Each sub‑pulse retains its own parent chain.
  • The onComplete, onError, and onProgress callbacks are preserved from the first pulse in the iterable, unless overridden via the named parameters. They are not applied to each individual pulse.
  • If the iterable is empty, the factory returns an empty collective with null payload and isComposite set to true.
  • The collective's root is itself (it's a root collective), but each sub‑pulse's root remains its own root.
  • The optional parameters (policy, context, type, source, step, priority, onComplete, onError, onProgress) apply to the collective as a whole, not to individual pulses. They override the corresponding values from the first pulse.

Example: Batching updates

final priceUpdate = Pulse<double>(99.99);
final stockUpdate = Pulse<int>(42);
final batch = Pulse.batch([priceUpdate, stockUpdate]);

// The payload is the collection of pulses
print(batch.payload); // [99.99, 42] (as Iterable<Pulse>)

// Process as a single wave
receptor.call(batch);

// Iterate to access individual pulses
for (final p in batch) {
  print(p.payload);
}
// Outputs: 99.99, 42

Example: Adding a step to all sub‑pulses

final collective = Pulse.batch([pulse1, pulse2, pulse3]);
final processed = collective
    .map((p) => p.withStep('validation'))
    .toList();
final batch = Pulse.batch(processed);

Example: Empty collective

final empty = Pulse.batch<int>([]);
print(empty.isComposite); // true
print(empty.payload); // null
print(empty.length); // 0

Example: Overriding collective metadata

final batch = Pulse.batch(
  [pulse1, pulse2, pulse3],
  context: PulseContext.userAction(actor: 'admin', reason: 'Batch update'),
  type: 'bulk_operation',
  priority: 80,
);
// All pulses in the batch share the same context, type, and priority

Parameters:

  • pulses: An iterable of Pulse instances to be bundled together. The iterable can be empty, in which case an empty collective is returned.
  • policy: Optional lifecycle governance policy for the collective.
  • context: Optional pulse context override for the collective. If not provided, the context from the first pulse is used.
  • type: Optional semantic type tag override for the collective. If not provided, the type from the first pulse is used.
  • source: Optional originating cell override for the collective. If not provided, the source from the first pulse is used.
  • step: Optional audit step description for the collective.
  • priority: Optional scheduling priority override for the collective. If not provided, the priority from the first pulse is used.
  • onComplete: Optional completion callback override for the collective.
  • onError: Optional error callback override for the collective.
  • onProgress: Optional progress callback override for the collective.

Returns:

A Collective Pulse containing all the provided pulses. The collective is iterable, and its isComposite property is true. The payload is the iterable of pulses itself. The context, source, type, and priority are taken from the first pulse (or overridden by the named parameters). The callbacks are taken from the first pulse (or overridden by the named parameters).

Differences from + operator:

Feature Pulse.batch([a, b]) a + b
Returns CollectivePulse CollectivePulse
Structure Flat bundle Flat bundle
Payload Iterable of pulses [a, b] Iterable of pulses [a, b]
Metadata override Yes (via named params) No (inherited from first)
Use case Explicit batching with overrides Quick combination

See also:

  • Pulse.+ – the binary operator for combining two pulses.
  • isComposite – to check if a pulse is a composite (collective or chain).
  • Iterable – collectives can be iterated over to access individual pulses.
