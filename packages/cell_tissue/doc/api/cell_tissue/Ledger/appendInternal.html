The internal append used by LedgerScope. External callers should not use this — entries must carry the deltas that only postProcessRule captures.

Non-obvious: appends are serialised on this ledger

seq is assigned from lastSeq + 1; two scopes running concurrently (overlapping graph.run calls allocate one scope each) used to race on it. Review fix: appends queue on an internal chain owned by the ledger, so seq assignment and the store write are serialised across scopes — overlapping runs produce entries in completion order instead of racing. Nested (awaited) runs were already safe through the scope chain.

Future<void> appendInternal({
  required Pulse pulse,
  required ApplyReceipt receipt,
  required String cellId,
  required List<EffectRecord> effects,
  required List<StateDelta> deltas,
}) {
  if (_closed) {
    throw StateError('Ledger is closed');
  }
  final task = _appendTail.then((_) => _appendInternalNow(
        pulse: pulse,
        receipt: receipt,
        cellId: cellId,
        effects: effects,
        deltas: deltas,
      ));
  _appendTail = task.catchError((_) {});
  return task;
}
