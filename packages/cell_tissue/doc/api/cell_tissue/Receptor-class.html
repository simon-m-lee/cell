Receptor

Receptor<C extends Cell> class abstract interface

The transformation pipeline that decides how a Cell responds to an incoming Pulse – return a pulse to continue propagation, or null to stop it there.

Where to start

  • Receptor.passThrough – the default; forwards the pulse unchanged. You'll never construct this yourself; it's what every Cell uses unless you provide something else.
  • Receptor((cell, pulse, {user}) => ...) – the primary constructor, for a single transformation/filter step. This covers most use cases.
  • Receptor.from – for a three‑stage pipeline (preProcess → rule → postProcess), useful when you want reusable validation/logging logic separated from the core transformation.

When to use

Use a custom receptor when you need to transform, filter, or react to pulses that arrive at a cell. Most cells use the default pass‑through, but you'll define a receptor for any custom logic – e.g., validation, mapping, side effects, or state updates.

How it works

A receptor is a functional wrapper around one or more PulseRules. When a pulse arrives, the receptor executes its pipeline and returns the resulting pulse or null. The receptor can be activated (bound to a specific cell) or used as a stateless template.

  • Pipeline stages: preProcess (sanitization) → rule (core logic) → postProcess (commitment/validation).
  • If any stage returns null, the pipeline stops and no further stages run.
  • Stages can be synchronous or asynchronous (FutureOr).
  • Exceptions are caught and reported via the pulse's onError callback.

Non‑obvious

  • Activation: A receptor built via the constructor is a stateless template (isActivated is false) until the framework binds it to a specific cell. Once activated, it holds a reference to that cell and cannot be safely reused on a different one – use clone for that.
  • Pass‑through: The passThrough constant is a singleton; millions of cells can share it without memory overhead.
  • Returning null is the standard way to filter – e.g., return value >= 0 ? pulse : null;. It's not an error path.
  • Cloning: If you need the same logic on multiple cells, call clone on an activated receptor to get a fresh, unactivated copy.

Example: Simple Transformation

final doubleReceptor = Receptor((cell, pulse, {user}) {
  final value = pulse.payload as int;
  return Pulse<int>(value * 2);
});

Example: Validated Pipeline

final validatedReceptor = Receptor.from(
  preProcess: PulseRule((cell, input, {user}) {
    print("Incoming: $input");
    return input;
  }),
  rule: PulseRule((cell, input, {user}) => Pulse(input.payload * 2)),
  postProcess: PulseRule((cell, input, {user}) {
    return (input.payload < 100) ? input : null;
  }),
);

See also:

  • PulseRule – the building block.
  • PulseRuleChain – for combining multiple rules.
  • TestCell – for validation (separate from transformation).
