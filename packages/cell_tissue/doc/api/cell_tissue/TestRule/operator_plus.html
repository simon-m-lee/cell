TestRule<C> operator +(
  1. covariant TestRule<C> other
)

Composes two TestRule instances into a sequential Validation Pipeline.

This operator implements the Chain of Responsibility pattern using Atomic Composition. It allows individual, granular rules to be linked together into a singular governance unit, facilitating the construction of complex policy layers from simple, stateless blueprints.

Developer Ergonomics & Human Legibility

This operator provides a clean, readable way to build validation pipelines:

final pipeline = isPositive + isInRange + isAuthorized;

// Equivalent to:
final pipeline = TestRule.chain([isPositive, isInRange, isAuthorized]);

1. Operational Mechanics: Sequential Logic

When rules are combined using +, they are evaluated in a specific order:

  • Execution Order: The current rule (the receiver) is evaluated first. If it passes, the other rule is then evaluated.
  • Short-Circuit Behavior: If the current rule returns false, the other rule is never executed, and the entire operation returns false immediately.
  • Cumulative Integrity: The resulting rule only returns true if both the principal rule and the other rule satisfy their invariants.

2. Hybrid Convergence: Seamless Propagation

The operator preserves Hybrid Convergence by automatically handling FutureOr returns. If the first rule in the chain returns a Future, the execution engine ensures the other rule is correctly awaited as part of the asynchronous reactive wave, maintaining Causal Integrity without manual intervention.

3. Architectural Role: Policy Layering

This operator is the primary mechanism for Policy Layering. It allows developers to build complex validation structures (e.g., IsString() + IsNotEmpty() + MaxLength(20)) without creating monolithic classes. Each link in the chain remains a stateless, reusable blueprint.

4. Example: Layered Validation

// Individual rules
final isNotNull = TestRule<String>((object, {host, arguments, user}) {
  return object != null;
});

final isNotEmpty = TestRule<String>((object, {host, arguments, user}) {
  return (object as String).isNotEmpty;
});

final maxLength = TestRule<String>((object, {host, arguments, user}) {
  return (object as String).length <= 50;
});

// Compose into a pipeline
final validString = isNotNull + isNotEmpty + maxLength;

// Usage
expect(await validString.call(null), false);
expect(await validString.call(''), false);
expect(await validString.call('Hello'), true);
expect(await validString.call('x' * 100), false);

Parameters:

  • other: The next TestRule to be appended to the validation chain. Uses covariant to ensure type compatibility with the host environment C.

Returns:

A new TestRule that encapsulates the sequential evaluation of both rules.

Implementation

TestRule<C> operator +(covariant TestRule<C> other) {
  return TestRule<C>.chain([this, other]);
}
