The foundational base class for Metadata-Driven Validation Annotations.

Classes extending TestRule (such as ValueRange, EntryPattern, and Values) allow for the declarative definition of Business Invariants directly on class fields. This enables the framework to automate data sanitization, schema generation, and UI state management.

1. Developer Ergonomics & Human Legibility

Developers use annotations to declare constraints declaratively:

class User {
  @ValueRange(min: 0, max: 120)
  final int age;

  @EntryPattern(pattern: r'^[^@]+@[^@]+\.[^@]+$')
  final String email;

  @MaxLength(50)
  final String name;

  @Values(['admin', 'editor', 'viewer'])
  final String role;
}

2. Architectural Role: Structural Constraints

As an annotation, a TestRule serves as a Static Blueprint for data integrity. It ensures that any Pulse payload entering a Cell adheres to the formal constraints defined in the source code before the state transition is committed.

3. SE Patterns: Stateless Validation

Most annotation-based rules extend TestRule<Never>, indicating they are Stateless Validators. They rely purely on the value of the input object and do not require access to a host container or external state variables.
