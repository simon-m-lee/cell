The advanced compositional factory for Receptor, enabling the creation of complex, multi-stage pulse processing pipelines.

When to use

Use this when you need to separate concerns: e.g., logging before transformation, then post‑validation. It's a three‑stage pipeline.

How it works

You provide up to three PulseRules: preProcess (runs first), rule (core logic), and postProcess (runs last). Each stage can filter or transform the pulse. If any stage returns null, the pipeline stops.

Non‑obvious

  • The stages are executed sequentially; the output of one is the input of the next.
  • This is the recommended way to separate validation from business logic.

Example: Validated Pipeline

final validatedReceptor = Receptor.from(
  preProcess: PulseRule((cell, input, {user}) {
    print("Incoming: $input");
    return input;
  }),
  rule: PulseRule((cell, input, {user}) => Pulse(input.payload * 2)),
  postProcess: PulseRule((cell, input, {user}) {
    return (input.payload < 100) ? input : null;
  }),
);

Parameters:

  • rule: The central PulseRule defining the primary transformation logic for the cell.
  • preProcess: An optional PulseRule executed before the main logic. Useful for sanitization or "Before" hooks.
  • postProcess: An optional PulseRule executed after the main logic. In ValueCell architecture, this is where the testRule is enforced before the state is committed to the Box.
