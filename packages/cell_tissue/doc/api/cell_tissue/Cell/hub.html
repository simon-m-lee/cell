Creates a Switching Fabric: a routing node that dispatches an incoming Pulse to one of several named handlers based on Pulse.type.

This is the basic-tier hub factory. Like Cell.value, Cell.ingress, and Cell.observe, it requires no knowledge of Context, DeputyContext, Receptor, or TestCell to use — you provide plain functions keyed by a role name, and the framework handles wiring, activation, and dispatch.

1. What it does

Each entry in spokes becomes an internal cell. When a pulse arrives at the hub with pulse.type == role, it is routed to that entry's handler. Handlers use the same closure shape as Cell.derive's transform or Cell.observe's onPulse — nothing new to learn.

2. Example

final hub = Cell.hub(
  spokes: {
    'Auditor': (cell, pulse, {user}) =>
        pulse.evolve(PulseContext(reason: 'AuditRecord'), step: 'audit'),
    'StateEngine': (cell, pulse, {user}) => pulse,
    'Telemetry': (cell, pulse, {user}) async {
      await remoteLogger.send(pulse.payload);
      return pulse;
    },
  },
);

hub.trigger(Pulse.governed(payload: auditEvent, type: 'Auditor'));

3. Routing mechanics

The default relay does a direct map lookup — spokes[Pulse.type] — with no runtime type casting involved. If Pulse.type doesn't match any key, the pulse is dropped silently at the hub (no spoke is triggered). Provide relay to override this and implement custom dispatch (e.g. broadcast to every spoke, or route on a computed key rather than Pulse.type).

4. Advanced: per-spoke governance

If individual spokes need distinct security tiers, clearance levels, or temporal leases, use governedSpokes instead of spokes. This exposes DeputyContext (to define each spoke's mandate) and Receptor (to define its handler logic) directly. Provide exactly one of spokes or governedSpokes, not both. Most applications will never need this path.

Parameters:

  • spokes: Maps a role name to its handler. Mutually exclusive with governedSpokes.
  • governedSpokes: Advanced. Maps a DeputyContext (mandate/role) to a Receptor for cases needing per-spoke authority tiers. Mutually exclusive with spokes.
  • bind: Optional upstream Cell to observe, making the hub reactive to another source in addition to manual trigger/ingest calls.
  • context: The hub root's own operational tier. Defaults to Context.system; safe to leave unset for basic use.
  • testRule: An TestCell guard applied to the hub's root ingress. Defaults to TestCell.allowAll.
  • distribution: Optional factory to customize each spoke's Synapses (e.g. to attach a PropagationPolicy), keyed by role name.
  • relay: Optional override for the default routing logic described above.
  • forceLock: If true, allocates a dedicated Lock for the hub root, guaranteeing sequential processing under high-frequency bursts.

Returns:

A HubHandle record: root (the ingress Cell), spokes (the internal spoke cells), trigger/triggerAsync (manual injection), and ingest (standard Pulse-based injection with serializedCompletion support).

See also:

  • Cell.derive for a single-output equivalent of a spoke handler.
  • Cell.observe for a terminal (non-propagating) handler shape.

static HubHandle hub({
  Map<String, FutureOr<Pulse?> Function(Cell cell, Pulse pulse, {dynamic user})>? spokes,
  Map<DeputyContext, Receptor>? governedSpokes,

  Cell? bind,
  Context context = Context.system,
  TestCell testRule = TestCell.allowAll,
  Synapses Function(String role)? distribution,
  void Function(Pulse pulse)? relay,
  bool forceLock = false,
}) {
  // Exactly one input mode is allowed. Both null or both non-null are
  // programmer errors, not runtime conditions — fail fast, at construction
  // time, before any Cell is allocated.
  assert(
  (spokes == null) != (governedSpokes == null),
  'Cell.hub requires exactly one of `spokes` or `governedSpokes`. '
      'Use `spokes` for the basic string-keyed router (no Context/Receptor '
      'knowledge needed). Use `governedSpokes` only if individual spokes need '
      'distinct DeputyContext authority tiers (clearance, lease, isolation).',
  );

  // Resolve both input modes to one common internal shape:
  //   Map<String role, Cell spokeCell>
  // This is the seam that keeps DeputyContext/Receptor entirely out of the
  // `spokes` path — by the time we get past this block, both paths look
  // identical to the rest of the method.
  final Map<String, Cell> spokeCells = spokes != null
      ? _spokesFromSimple(spokes, distribution: distribution)
      : _spokesFromGoverned(governedSpokes!, distribution: distribution);

  final receptor = Receptor((cell, input, {user}) => input);
  final cell = Cell.governed(
    context: context,
    receptor: receptor,
    testRule: testRule,
    synapses: Synapses(
      downstreams: spokeCells.values,
      relay: relay ?? (pulse) {
        // Direct map lookup, keyed by the pulse's own declared type.
        // No cast, no reflection into a spoke's governance context — this
        // is what removes the (DeputyContext) cast and its associated
        // runtime TypeError risk from the original implementation.
        final spoke = spokeCells[pulse.type];
        spoke?._nucleus.receptor.call(pulse);
      },
    ),
    bind: bind,
    forceLock: forceLock,
  );

  Pulse? trigger(Pulse pulse) {
    final result = receptor.call(pulse);
    return result is! Future ? result : null;
  }

  Future<Pulse?> triggerAsync(Pulse pulse) {
    final lock = cell._nucleus.lock;
    if (lock != null) {
      return lock.synchronized(() => trigger(pulse));
    }
    return Future<Pulse?>(() => trigger(pulse));
  }

  Future<void> ingest(Pulse pulse, {bool serializedCompletion = true}) {
    return receptor.async.call(pulse as PulseBase, serializedCompletion: serializedCompletion);
  }

  return (root: cell, spokes: spokeCells.values, trigger: trigger, triggerAsync: triggerAsync, ingest: ingest);
}
