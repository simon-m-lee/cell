Activates a live Cell instance from a pre-configured Nucleus.

This factory serves as the primary Node Hydration Engine for the framework. It allows for the direct instantiation of a reactive node from an existing property record, providing precise architectural control over the node's behavioral logic, synchronization domain, and structural identity.

Purpose & Architectural Role:

The fundamental purpose of fromNucleus is to facilitate Explicit Node Activation and State Restoration. Within the framework's memory-efficient architecture, the Nucleus acts as the "Static Configuration" (logic, rules, and identity), while the Cell acts as the "Live Instance" (the active, stateful node).

This constructor is essential for:

  1. Relational Reconstitution: Reconstructing a graph node from a serialized or persisted property set while ensuring it adheres to the original's behavioral contract.
  2. Prototype-Based Instantiation: Working in tandem with Nucleus.clone or Nucleus.evolve to create new graph nodes that replicate or shadow a specific configuration.
  3. Dependency Injection: Allowing the framework or advanced providers to inject a fully-formed property record—including a specific synchronization Lock and Synapses configuration—directly into a new node.

The Proxy Pattern & Inheritance:

This factory is the underlying mechanism for the Proxy Pattern. When a Nucleus is extended (creating a child configuration with localized overrides), this factory "activates" that extension into a live proxy.

  • The resulting cell shares the Physical Data Source (and potentially the Lock) of its principal but operates under the specific Context and TestCell rules defined in the provided nucleus.
  • This allows for the creation of multiple specialized "Views" of the same underlying data source, each with different permissions or execution priorities.

Synchronization & Atomic Integrity:

The resulting instance inherits the optional synchronization domain (the Lock) defined within the nucleus. If a lock is provided, it ensures that the cell enters the Directed Acyclic Graph (DAG) as a thread-safe, atomically consistent node. This mechanism allows developers to group multiple cells into a single Atomic Transaction Domain by sharing a common lock.

Human Developer Usage

This factory is primarily used by framework internals and advanced developers. Most developers should use the simpler Cell factory.
