SyncBox

SyncBox<T> class

A synchronized variant of Box that provides thread-safe access and facilitates atomic state transitions.

In the reactive framework, SyncBox implements the Synchronized State Anchor pattern. While a standard Box is optimized for high-performance, single-threaded propagation within a reactive wave, SyncBox is designed for Conactive Integrity—ensuring that state remains consistent even when accessed or mutated across concurrent execution contexts.

1. Architectural Role: Thread-Safe Proxy

SyncBox serves as the primary storage gateway for nodes that require strict Mutual Exclusion. It is a cornerstone of the framework's concurrency model, preventing "State Tearing" or race conditions during high-frequency updates from multiple asynchronous sources (such as hardware interrupts, network callbacks, or background isolates).

2. Functional Mechanics: Atomic Commitment

Unlike a standard Box, which allows direct imperative access, SyncBox is architecturally positioned to work with the framework's locking mechanisms:

  • Serialization: Access to the underlying value is gated by an internal Lock, ensuring that only one Receptor or actor can modify the state at a time.
  • Visibility Guarantees: It ensures that once a value is written, it is immediately visible to all subsequent readers across different execution contexts, maintaining a Linearizable state history.
  • Asynchronous Interface: All operations return Futures, signaling to the framework that the operation involves a synchronization barrier and may yield execution.

3. Use Cases in the Conactive Engine

  • Shared Resources: Used in cells that wrap external asynchronous drivers (e.g., a shared sensor buffer or a database connection).
  • Cross-Context Signals: Acting as a stable memory bridge when Pulse signals originate from background worker isolates.
  • Orchestration Nodes: Storing shared configuration in complex system hierarchies where multiple agents may read/write simultaneously.

See also:

  • Box: The standard mutable variant for high-speed reactive flow.
  • FinalBox: The write-once variant for late-binding immutability.
