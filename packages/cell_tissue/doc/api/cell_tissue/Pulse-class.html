Pulse

Pulse<P> class abstract interface

An immutable signal carrying a payload through the reactive graph.

Every pulse also carries its own history: parent links to the pulse it was derived from, trace records the steps it's been through, and root always points to the original. You rarely need this trail directly — it exists so the framework (and TestCell rules) can reason about a signal's provenance — but it explains why payload, context, and timestamp are resolved by walking up to the root rather than stored fresh on every derived pulse.

Where to start

  • Pulse(value) — the constructor you'll use almost everywhere.
  • Pulse.governed — adds actor/reason/priority/sensitivity metadata, for cases where that provenance matters (audit trails, security rules). Prefer the plain constructor unless you have a specific reason not to; the governed form exists for the ~10% of cases where accountability needs to be explicit.
  • evolve — derive a new pulse from this one (e.g. after a transformation step), keeping the parent link intact.
  • withStep — shorthand for evolve when you're just appending to trace without changing context.
  • + operator — combines two pulses into a CollectivePulse for atomic processing together.
  • Pulse.batch — combines multiple pulses into a CollectivePulse for atomic processing together.

Non-obvious: collective pulses

pulseA + pulseB creates a CollectivePulse – a flat bundle where each pulse retains its independent identity. The bundle is iterable and exposes a single payload (from the first pulse) for backward compatibility. Iterate the pulse itself to access each member individually.

Non-obvious: evolved pulses

pulse.evolve(step: '...') creates an EvolvedPulse – a chain where the new pulse is linked to its parent via the parent property.

Non-obvious: unmodifiable

Once wrapped, evolve throws instead of producing a new pulse. Use this before handing a pulse to code you don't trust to keep deriving from it — e.g. before logging or passing to an external callback.

See also: PulseContext (the metadata attached via Pulse.governed), Receptor (what actually consumes a pulse), PulseEphemeralPolicy (TTL/hop-limit governance for long-lived pulses).
