TissueEvent

TissueEvent enum

Defines the core categories of structural change events emitted by a Tissue collection during state mutations.

In the biological metaphor of the framework, TissueEvent acts as the Nervous Signaling Vocabulary for reactive collections. When a mutation occurs (such as an element addition or a scalar update), the tissue broadcasts one of these event types wrapped inside a TissuePulse to notify downstream observers and UI layers.

When to use

  • Reactive Pattern Matching: Use these enums in switch statements or if conditions within .listen() or .observe() callbacks to handle specific collection mutations.
  • Auditing and Logging: Filtering out routine updates versus structural reorganizations in forensic audit pipelines.
  • Optimized UI Rendering: Determining whether a widget needs to insert a new item, remove an element, or perform an in-place property update.

How it works

Each enum value corresponds to a specific mutation pathway in the tissue:

  • elementAdded: Emitted when one or more elements are appended or inserted.
  • elementRemoved: Emitted when elements are purged or popped.
  • elementUpdated: Emitted when a scalar value or property changes.
  • entryUpdated: Emitted when a key-value pair within a collection mutates.

Non‑obvious

  • Post-Mutation Emission: Events are strictly emitted after the mutation has successfully passed all integrity gates and has been applied to the backing container.
  • Batching Awareness: In a collective pulse, multiple events may travel together under a unified batch type, but individual sub-events retain their specific TissueEvent classification.

See also:

  • TissuePulse – The structural signal carrying these event classifications.
