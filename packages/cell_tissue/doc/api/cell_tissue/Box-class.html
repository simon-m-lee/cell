Box

Box<T> class

A specialized, lightweight container used to provide a mutable state/// anchor within the framework's immutable Record architecture.

In the reactive ecosystem, the Box is the primary vehicle for Identity-Preserving State Updates. While the Nucleus and its underlying records are strictly final to ensure architectural stability, the Box allows the framework to update a cell's internal data without reallocating the entire configuration tree.

1. Architectural Role: The Flyweight State Container

To achieve high-density scalability, the framework utilizes the Flyweight Pattern. Most of a node's memory footprint is stored in a shared, immutable Nucleus. The Box serves as the minimal "Variable Segment" of that footprint:

  • Record Integration: A Box is typically stored within the extensions segment of a nucleus record.
  • Pointer Stability: Because the Box instance itself is final within the record, the structural blueprint remains immutable even as the content of the box evolves.
  • Memory Efficiency: By wrapping only volatile state, the framework avoids the overhead of traditional class-heavy state management for every node in the graph.

2. Functional Mechanics: The Transformation Bridge

The Box acts as the bridge between a Receptor and the node's storage:

  • State Persistence: During a "Propagation Wave," the Receptor extracts the current value from the box, performs a mapping transformation, and writes the new result back.
  • Type Safety: The box preserves the generic type T of the node's state, ensuring that Pulse processing remains type-safe at the storage layer.
  • Nullable Flexibility: A box can hold a null value, representing an uninitialized or reset state.

3. Conactive Synchronization (async)

Every Box provides a SyncBox via the async property. This property implements the Synchronized Proxy pattern, allowing the same physical state to be accessed via:

  • Synchronous Access: Directly through value for high-performance reactive propagation within a single thread.
  • Asynchronous Access: Through async.set() or async.value to ensure Conactive Integrity and thread-safety when updates originate from external asynchronous drivers.

Example Usage:

// A nucleus extension stored in a record:
final extension = (state: Box<int>(0), category: 'counter');

// Updating the state through the box
extension.state.value = (extension.state.value ?? 0) + 1;

See also:

  • FinalBox: A variant for late-bound, immutable constants.
  • SyncBox: The thread-safe wrapper provided by the async property.
