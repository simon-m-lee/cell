DivergenceReport

DivergenceReport class

A single point at which a replay diverged from its recording.

How it works

The report is designed to be actionable. It carries:

  • seq — which ledger entry diverged. A human reading the report can grep 'seq: 47' ledger.jsonl and see exactly what was recorded.
  • expected / actual — the divergence's observable values. For a delta mismatch, these are the after values; for a receipt mismatch, the receipt digests; for a journal mismatch, the effect fingerprints.
  • lastEffect — the last effect the replay consumed before diverging. This is what tells you "the receptor reached the network call at ordinal 5, then diverged" — the single most valuable diagnostic for an effectful receptor that has changed.
  • reason — a human-readable explanation.

Non-obvious: the report is per-divergence, not per-pulse

A single pulse can produce multiple divergences (a delta mismatch and a receipt mismatch), which is why ReplayResult.divergences is a list of DivergenceReports, not a single report. The CLI's replay diff prints them all; ReplayEngine in strict mode throws on the first.

See also:

  • ReplayResult — the list these reports accumulate into.
  • ReplayDivergenceException — what strict replay throws.
