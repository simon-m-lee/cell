Creates a specialized Architectural Extension of an existing Nucleus to support hierarchical property inheritance and contextual overrides.

This constructor is the core implementation of the Prototype Inheritance Pattern (specifically the Proxy/Deputy Pattern) within the property system. It allows a derived nucleus to inherit its structural identity and core behavioral logic from a principal while layering on localized configuration overrides.

1. Purpose & Architectural Role: Contextual Specialization

The fundamental purpose of .evolve is to facilitate Behavioral Specialization with minimal memory overhead. In a complex reactive graph, many nodes may share the majority of their logic (e.g., security tiers, validation rules, or physical storage strategies) but differ in a single specific aspect.

Instead of re-allocating a full property set for every variation, this constructor creates a "Linker Record" that points back to the principal for any property not explicitly defined in the local scope. This is critical for:

  • Creating Proxies: Generating restricted-access or read-only views (Deputies) of a cell that share the same data but use different validation testRules.
  • Contextual Projections: Running the same logic under a different context (e.g., projecting a system-level state into a user-level view).
  • Behavioral Shadowing: Overriding a receptor to add transformation logic without altering the principal blueprint's original behavior.

2. Functional Behavior: The Resolution Chain

This constructor establishes a vertical link in the configuration tree. When a property is accessed, the system employs a recursive "walk-up" strategy:

  1. Local Override: It first checks the local record for overrides provided directly to this .evolve call.
  2. Parental Fallback: If the property is missing locally (omitted for memory efficiency), the system "walks up" the inheritance chain to the principal.
  3. Terminal Defaults: The chain continues until it eventually falls back to global framework defaults (terminating at Nucleus.empty).

3. Synchronization Domain (Lock Inheritance)

A key feature of evolved extensions is their relationship with the principal's synchronization primitive:

  • Shared Atomicity: By default, extensions share the principal's atomic Lock. This ensures that the principal and its proxies maintain a single atomic boundary for complex graph transitions.
  • Isolation: If an override is provided and it contains its own lock, the extension can effectively branch into an independent synchronization domain.

Parameters:

  • ephemeralPolicy: Optional. A Lifecycle Governance Policy defining how and when the resulting cell should be automatically invalidated.
  • bind: Optional. A Cell dependency. Note: bindings are instance-specific and are not inherited from the principal. (Ignored if override is set).
  • context: Defines the execution tier and operational authority. If null, resolves from the principal. (Ignored if override is set).
  • receptor: The Transformation Pipeline logic. (Ignored if override is set).
  • testRule: Policy Guard rules for state changes. If null, inherits from the principal. (Ignored if override is set).
  • synapses: Egress Network management. Determines if the node maintains its own observer list. (Ignored if override is set).
  • user: Optional ad-hoc metadata or extension-specific storage.
  • override: Optional. A pre-compiled Nucleus whose record will be directly adopted as the property base.
  • principal: Required. The source Nucleus from which this instance derives its structural and logic inheritance.
