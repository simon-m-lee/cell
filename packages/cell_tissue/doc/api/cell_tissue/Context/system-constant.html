system

system constant

_ContextSystem const system

The canonical root context for the entire framework, acting as the Terminal Ancestor in the system's Prototype-based Inheritance model.

In the framework's architecture, system serves as the ultimate fallback for all ontological lookups. It defines the global "Safe Mode" and default operational parameters for any Cell that has not been specialized into a specific domain.

Developer Ergonomics & Human Legibility

This is the default context used when no explicit context is provided:

// Default context for all cells
final cell = Cell(); // context = Context.system

// Safe default for most applications
final context = Context.system;
print(context.domains); // null
print(context.constraints); // null

1. Architectural Role: Global Baseline & Fallback

Every Context eventually descends from system. It ensures that even in an unconfigured or embryonic state, a node possesses:

  • Baseline Security: Minimal Ontology.constraints that permit standard framework operations while maintaining fundamental integrity.
  • Default Domains: Categorization under the core system domain to ensure the node is visible to the framework's diagnostic and auditing layers.
  • Standard Governance: Inherited Mandate and Clearance defaults to prevent "Authority Vacuum" errors during a pulse transmission.

2. Hybrid Convergence: Zero-Cost System Access

As a static const, the system context is pre-compiled and shared across all reactive nodes. This supports Hybrid Convergence by providing a zero-cost path for permission checks.
