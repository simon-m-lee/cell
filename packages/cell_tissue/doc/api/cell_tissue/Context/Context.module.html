Creates a Module-Level Context for domain-specific logic, feature components, and specialized state atoms.

In the framework's Scene-Driven Ontology, a module context identifies "User-Space" logic. It serves as the primary organizational unit for the functional features of an application and defines the Sovereign Resident profile for a feature's logical boundary.

When to use

Use this for application‑level logic – e.g., payment processing, user management, or any business domain.

How it works

The factory sets domains: 'logic', taxonomy: 'module', and a default priority of 10. You provide a label (stored in partOf).

Example

final paymentContext = Context.module('PaymentEngine');

Parameters:

  • label: The human-readable identifier for this functional unit (e.g., 'AuthModule', 'PaymentEngine', 'UserAccount').
  • others: Catch-all for domain-specific metadata, such as feature-flags or versioning identifiers.

Implementation

factory Context.module(String label, {Map<String, dynamic>? others}) =>
    Context.fromEntries(
      [
        Ontology.partOf.entry(label),
        Ontology.taxonomy.entry('module'),
        Ontology.domains.entry('logic'),
      ],
      others: {
        'priority': 10, // Standard priority for logic modules
        ...?others,
      },
    );
