ApplyRejected

ApplyRejected<R> class final

The command was denied by the framework's safety rules (the Integrity Gate).

ApplyRejected is the "denial receipt" returned when an action is not allowed to proceed. It signifies that the request was intercepted before it could change any state, keeping the reactive graph safe.

In the framework's biological metaphor, this represents a Blocked Signal where the cell's "Integrity Gate" determined the mutation was incompatible with the current DNA.

Why it is used

  • Safety Enforcement: It confirms that the TestCell.action rules successfully prevented an invalid or unauthorized change.
  • Feedback: It provides a reason explaining why the rejection happened, allowing the UI or the calling logic to react appropriately.
  • Forensic Logging: Even though the action failed, the receipt captures the attempt, providing an audit trail of "Who tried to do what" that was denied.

How it works

If a command fails the vetting process, the framework stops execution immediately and returns this object. Because ApplyOutcome is sealed, you can use pattern matching to safely handle the rejection and display the reason to the user.

Technical Details

  • Result Type R: The class still carries the type R to remain compatible with the expected success type, but it contains no actual result data.
  • Optional Reason: The reason can be any object—a simple string, an error code, or a complex validation object—depending on what the Integrity Gate provided.
