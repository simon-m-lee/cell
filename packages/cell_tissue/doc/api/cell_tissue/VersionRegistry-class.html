VersionRegistry

VersionRegistry class

Maps (cellId, version) to the receptor and test rule that implemented that version.

When to use

The replay engine's ReplayEngine consults the VersionRegistry first: if the registry has an entry for (cellId, version), that is used; otherwise, the live receptor is used only if its version matches the ledger's; otherwise, replay fails loudly.

Non-obvious: the registry is graph-scoped, not process-wide

Two graphs in the same process may have the same cell name with different version histories (a test graph and a production graph). A process-wide registry would allow the test graph's version to shadow the production graph's, which is exactly the kind of ambient coupling the governance layer exists to prevent. The registry is created lazily by CellGraphVersions.versions and lives for the graph's lifetime.

See also:

  • CellGraphVersions — the per-graph extension that owns a registry.
  • ReplayEngine — consults the registry at each version boundary.
