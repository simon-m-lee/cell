IngressHandle

IngressHandle<I> typedef

IngressHandle<I> = ({Cell cell, Future<void> Function(Pulse<I> pulse, {bool serializedCompletion}) ingest, bool Function(I input) trigger, Future<bool> Function(I input) triggerAsync})

A management handle for an Input Gateway, providing a controlled interface for injecting external imperative stimuli into the reactive graph.

In the Cell architecture, an IngressHandle serves as the Imperative-to-Reactive Bridge. It provides the primary mechanism for non-reactive components—such as UI event handlers, hardware sensors, or network callbacks—to initiate state transitions within a synchronized, Scene-Driven Ontology.

When to use

You get this from Cell.ingress. Use it when you need to inject external events (like button clicks, WebSocket messages, or sensor readings) into the reactive graph.

How it works

The handle wraps a cell and provides three ways to send data:

  • trigger: synchronous, immediate update.
  • triggerAsync: asynchronous, lock-protected update.
  • ingest: full Pulse injection with provenance.

Non‑obvious

  • If the cell has a Lock (via forceLock: true), triggerAsync queues the update to prevent race conditions.
  • The ingest method with serializedCompletion: true waits for the entire graph to stabilise before the Future completes.

Type Parameters:

  • I: The raw input data type accepted by this gateway.

Implementation

typedef IngressHandle<I> = ({

  /// The source node ("cell") that anchors this entry point to the graph.
  Cell cell,

  /// Synchronously injects a stimulus into the reactive graph at **Native Speed**.
  ///
  /// Returns `true` if the transformation and validation were successful.
  bool Function(I input) trigger,

  /// Asynchronously injects a stimulus into the reactive graph, ensuring
  /// **Serialized Transformation** through the node's **Conactive Lock**.
  ///
  /// ### Operational Logic:
  /// *   **Lock Integration**: If the [cell] is governed by an atomic [lock],
  ///     this method wraps the execution in a `synchronized` block.
  /// *   **Fallback Path**: If no lock is available, it returns a [Future]
  ///     that executes the transformation in the next available microtask.
  ///
  /// Returns a [Future<bool>] resolving to `true` if the signal passed the
  /// **Integrity Gate** and the resulting **Reactive Wave** successfully propagated.
  Future<bool> Function(I input) triggerAsync,

  /// The **Primary Ingress Handle** for direct **Signal Orchestration**.
  ///
  /// This method allows for the injection of a fully-formed [Pulse],
  /// bypassing the standard transformation mapping for complex scenarios.
  ///
  /// ### The Consequence of `serializedCompletion`:
  /// *   **Wave Atomicity (`true`)**: The returned [Future] acts as a
  ///     **Stabilization Barrier**. It only resolves once the injected pulse
  ///     has fully propagated through the graph and all downstream
  ///     side-effects have reached a stable state.
  /// *   **Fire-and-Forget (`false`)**: The [Future] resolves as soon as the
  ///     pulse is accepted by the ingress buffer, allowing for high-throughput
  ///     background processing.
  Future<void> Function(Pulse<I> pulse, {bool serializedCompletion}) ingest
});
