Creates a derived version of this pulse, adapted for the next stage of the processing chain.

When to use

Use this when you need to change a pulse's context (authority, reason, priority) without losing its causal history – e.g., after a transformation step.

How it works

You provide a new pulse (to append to the chain), a step description, and/or a new context. The new pulse links back to this one via parent, so the history is preserved.

Non‑obvious

  • You must provide at least one of pulse, step, or context.
  • The payload is inherited from the root – you can't change it here.
  • The new pulse gets a fresh trace entry with the step.
  • If you provide a pulse, the new pulse becomes an EvolvedPulse that carries the new pulse as its payload.

Example

final root = Pulse<int>(42);
final evolved = root.evolve(step: 'sanitization');
print(evolved.trace); // ['sanitization']
print(evolved.payload); // 42 (inherited from root)

Parameters:

  • pulse: An optional pulse to append to the chain.
  • step: A descriptive string to be added to the chronological trace log.
  • context: A new PulseContext containing the updated Mandate and Provenance for the derived signal.

Returns:

A new Pulse instance representing the updated state of the message with its causal lineage preserved.

Implementation

@override
Pulse evolve({Pulse? pulse, String? step, covariant PulseContext? context}) {
  assert(
  (pulse == null) && (step == null) && (context == null),
  'Pulse.evolve requires at least `pulse` or `step` or `context` is not null.',
  );

  if (pulse == null && context == null) {
    return _Pulse<P>(step: step, parent: this);
  }

  return pulse is Pulse<P>
      ? _EvolvedPulse<P>(context: context, step: step, pulse: pulse, parent: this)
      : _EvolvedPulse(context: context, step: step, pulse: pulse, parent: this);
}
