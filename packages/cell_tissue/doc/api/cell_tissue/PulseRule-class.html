PulseRule

PulseRule<C extends Cell, I extends Pulse, O extends Pulse> class abstract interface

A reusable unit of logic for processing and transforming Pulse instances.

PulseRule is the building block for Receptor pipelines. It takes an incoming pulse and either transforms it into a new pulse or drops it by returning null. Rules are stateless and composable – you can chain them with the + operator to form sequential pipelines.

Where to start

You rarely need to implement PulseRule directly. Instead, use the Receptor factory with a simple function:

final receptor = Receptor((cell, pulse, {user}) {
  final value = (pulse.payload as int) * 2;
  return Pulse(value);
});

For reusable logic, define a PulseRule and compose it:

final doubleRule = PulseRule<int, int>((cell, pulse, {user}) {
  return Pulse(pulse.payload * 2);
});
final receptor = Receptor(rule: doubleRule);

When to use

Use PulseRule when you need to encapsulate a transformation or filter that can be reused across different receptors. It's the standard way to build complex processing pipelines from small, focused pieces.

How it works

  • A rule receives the host cell, the incoming pulse, and optional user data.
  • It returns a new pulse (to continue propagation) or null (to drop it).
  • Rules are composable using + – the output of one becomes the input of the next. If any rule returns null, the chain short‑circuits.
  • Rules are stateless – all state is stored in the pulse or cell.
  • Rules can be synchronous or asynchronous (FutureOr).

Non‑obvious

  • The + operator creates a PulseRuleChain that preserves the order.
  • If a rule throws an exception, the error is caught and logged, and the original pulse is returned as a fallback – ensuring resilience.
  • Rules are flyweight – they store configuration in a compact record, so many rules can share the same logic without memory overhead.
  • The user parameter is passed to the rule function and can be used for configuration, but it's not part of the pulse's context.

Example: Validation Pipeline

final validateRule = PulseRule<String, String>((cell, pulse, {user}) {
  final text = pulse.payload;
  return text != null && text.isNotEmpty ? pulse : null;
});

final sanitizeRule = PulseRule<String, String>((cell, pulse, {user}) {
  return Pulse(pulse.payload.trim());
});

final pipeline = validateRule + sanitizeRule;

Type Parameters:

  • C: The type of the Cell that provides the context for this rule.
  • I: The type of the incoming Pulse (input).
  • O: The type of the resulting Pulse (output).

See also:

  • Receptor – the pipeline that uses rules.
  • PulseRuleChain – the composite of multiple rules.
