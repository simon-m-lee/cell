SyncQueue

SyncQueue<E> class

A thread-safe implementation of a PriorityQueue, providing Synchronized Access for prioritized collection-based state.

In the reactive framework, the SyncQueue serves as a Concurrency-Safe Execution Buffer. It ensures that the sequence of processing is governed by Priority Precedence rather than simple arrival time, while remaining atomically consistent across asynchronous triggers and multi-threaded execution contexts.

Architectural Role: Weighted Integrity

This implementation wraps a PriorityQueue with a non-recursive Lock to serialize access to the underlying binary heap. It prevents "State Tearing"—a condition where structural mutations (like add or removeFirst) occur simultaneously with reads, which could lead to corrupted reactive waves or invalid priority transitions.

Implementation Details:

  • Async Interfacing: Access to the internal queue is governed by asynchronous Future handles, aligning with the framework's non-blocking concurrency model.
  • Capacity Management: Supports an optional capacity constraint, acting as a "Resource Limit" to prevent memory bloat within the dependency graph.
  • Performance Note: Optimized for structural safety. For high-frequency read-only iterations, consider using replicate to obtain a point-in-time snapshot.
