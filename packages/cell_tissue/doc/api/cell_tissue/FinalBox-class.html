FinalBox

FinalBox<T> class

A specialized, write-once container that provides a thread-safe, immutable anchor for state that is initialized after construction.

In the reactive framework, FinalBox implements the Late-Binding Immutability pattern. It allows the system to define a property within a Nucleus or Static Configuration as "pending," ensuring that once the value is eventually committed, it remains strictly constant for the remainder of the node's lifecycle.

1. Architectural Role: Late-Bound Constants

Within the cell_core ecosystem, many components—such as specialized Receptor logic, unique Cell identifiers, or structural Blueprints— cannot be determined at the exact moment of the node's instantiation. FinalBox solves this by:

  • Placeholder Integrity: Acting as a stable pointer within an otherwise immutable record while the actual data is being computed or injected.
  • The Write-Once Contract: Utilizing Dart's late final semantics to enforce that any attempt to re-initialize or evolve the value after its first assignment results in a runtime error.
  • State Crystallization: Ensuring that once a node's Source of Truth is established, it cannot be tampered with, preserving the long-term integrity of the reactive graph.

2. Functional Mechanics: Initialization Governance

Unlike a standard Box, which acts as a mutable bridge, FinalBox governs the transition from a Stateless Blueprint to a Crystallized Instance:

  • Hydration Sequence: It is ideal for properties that depend on the node's activation status. The value can be set during the Ingress sequence and locked immediately thereafter.
  • Memory Stability: Because the container itself is a final object within the Nucleus, it maintains the framework's Flyweight Pattern requirements while allowing for flexible, multi-stage initialization.

3. Use Cases in the Conactive Engine

  • Dependency Injection: Storing an upstream Cell reference that is resolved asynchronously or through a factory method.
  • One-Time Computations: Wrapping the result of an expensive architectural setup (like a complex policy guard chain) that should be cached permanently.
  • Identity Anchoring: Holding a unique cryptographic hash or system-wide identifier generated at the moment of a node's first Pulse ingestion.

Example Usage:

// Defined within an immutable nucleus record
final config = (id: FinalBox<String>(), category: 'Secure');

// Initialization (allowed exactly once)
config.id.value = 'NODE_7741';

// Subsequent attempts to modify will throw
// config.id.value = 'NODE_8888'; // Late initialization error
