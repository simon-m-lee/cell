SyncSet

SyncSet<E> class

A thread-safe implementation of a Set, providing Synchronized Access for collection-based state.

The SyncSet serves as a Concurrency-Safe Container. It ensures that the membership of a set (such as the collection of active Synapses or dependency nodes) remains atomically consistent even when accessed or mutated across different reactive waves or asynchronous execution threads.

1. Architectural Role: Concurrent Integrity

This implementation uses a non-recursive Lock to serialize access to the underlying storage. It is designed to prevent "Collection Tearing"—a condition where one thread reads the set while another is mid-mutation, leading to inconsistent reactive waves or corrupted state snapshots.

2. Asynchronous Interface: Non-Blocking Access

Unlike standard synchronous sets, SyncSet utilizes Future-based Accessors. This aligns with the framework's non-blocking concurrency model, ensuring that the calling thread never blocks while waiting for the internal synchronization lock to release.

3. Operational Mechanics:

  • Atomic Mutations: Operations like add, remove, and clear are serialized through the internal Lock, ensuring that the collection membership is updated as a single, indivisible unit.
  • Snapshot Iteration: The iterator provides access to a Point-in-Time Snapshot of the set. This prevents ConcurrentModificationError by allowing the system to iterate over a stable copy while the primary set undergoes further concurrent updates.
  • Relational Operations: Set operations like intersection and union return standard Set objects, representing an immutable "Resultant View" of the interaction between two collections.

4. Performance Note:

This set is optimized for Structural Safety and thread synchronization over high-frequency throughput. In scenarios requiring mass-iterations or intensive read-only processing, it is recommended to use replicate to obtain a local, non-synchronized copy.

Type Parameters:

  • E: The type of elements contained within the synchronized set.
