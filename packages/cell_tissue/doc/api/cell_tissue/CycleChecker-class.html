CycleChecker

CycleChecker class

A utility for Circular Dependency Detection within the reactive graph.

The CycleChecker is a traversal guard used during the propagation of a Pulse. Its primary responsibility is to track the set of reactive nodes (Cells) that have already participated in a specific execution wave, ensuring that the system remains a Directed Acyclic Graph (DAG) and preventing infinite recursion.

1. Architectural Role: Graph Integrity

In a complex reactive network, nodes often have interdependent relationships. Without a cycle detection mechanism, a change in Cell A that triggers Cell B, which in turn triggers Cell A, would result in a stack overflow.

  • Path Tracking: It maintains a transient set of "visited" nodes for the duration of a single pulse propagation.
  • Traversal Guarding: Every Receptor uses this checker before executing its transformation pipeline. if a node is already present in the set, the propagation is halted for that specific branch.

2. Thread Safety & Concurrency

While the standard CycleChecker is optimized for synchronous, single-threaded execution, it provides a SyncCycleChecker (via the async getter) for Cross-Thread Synchronization. This utilizes an atomic Lock to ensure that visited sets remain consistent when a pulse spans across asynchronous boundaries.
