The High-Performance Collection Layer for Digital Organisms

The Vision: Specialized Tissues

In the biological world, complex life is made possible by tissues—collections of specialized cells working in concert to perform a unified function. cell_tissue brings this evolutionary leap to the Cell Framework.

While cell.core manages individual "unicellular" logic, cell_tissue provides the infrastructure for multicellular coordination. It transforms standard Dart collections (List, Set, Map, Queue) into reactive, self-governing "tissues" where every element is a participant in the system's nervous system.

Philosophy: Granular Reactivity

Traditional reactive collections often suffer from "all-or-nothing" invalidation. If one item in a list of 10,000 changes, the entire list is often marked as dirty.

cell_tissue implements Granular Reactivity:

  • Per-Element Pulsing: Pulses only fire for the specific elements that were added, removed, or modified.
  • Zero-Copy Views: Using the Deputy Pattern, you can create filtered or read-only "projections" of a collection that share the same physical memory.
  • Recursive Linking: Collections automatically propagate signals from their member Cells, allowing a change in a deep object to ripple through the tissue without global rebuilding.

Key Features

  • Full Reactive Suite: Specialized support for List, Set, Map, Queue, and single Value nodes.
  • Conactive Consistency: Every mutation is atomic and synchronized via internal Locks, preventing race conditions in complex reactive graphs.
  • Digital DNA (Nucleus): Shared, immutable blueprints for collection behavior, using Flyweight Records to minimize memory footprint.
  • Composable Immune System: Use the + operator to stack TestTissue rules across multiple deputies.
  • Semantic Metadata: Full integration with Context for domain-aware and AI-ready collections.
  • Recursive Unmodifiability: Deeply protect entire collection hierarchies with a single .unmodifiable call.

Core Concepts

Tissue: The Reactive Tissue

A Tissue<E> is a specialized Cell that also functions as an Iterable<E>. It acts as the "organ" managing a group of signals. It handles the lifecycle of its members and ensures structural integrity.

TissueNucleus: Tissue DNA

The TissueNucleus is the blueprint. It defines the storage strategy (e.g., list, set), the validation rules, and the pulse processing logic. Because it uses Flyweight Sparse Records, you can instantiate thousands of collections with virtually no memory overhead.

TissueReceptor: Pulse Coordination

The "brain" of the collection. It intercepts incoming signals (TissuePost) and manages how state is updated. It can prune redundant events and ensure that only meaningful changes propagate downstream.

TestTissue: The Tissue Immune System

The validation layer for collections. It allows you to define:

  • Element Rules: Constraints on what types of data can enter the collection.
  • Action Rules: Permission-based restrictions on methods like add, remove, or clear.
  • Structural Rules: Constraints on size, uniqueness, or ordering.

The Deputy Pattern in Collections

The Deputy Pattern is a first-class citizen in cell_tissue. It allows you to project a collection into different "roles":

  1. Read-Only Projections: .unmodifiable creates a view that prevents all structural changes.
  2. Role-Based Security: Create a deputy that adds an adminOnly rule on top of a public collection.
  3. Filtered Perspectives: View a subset of a collection without creating a new physical list.

AI-Native: The Semantic Collection Tier

cell_tissue is built for Agentic AI. Every collection carries a Context containing semantic metadata (domains, stakeholders, compliance tags).

How AI interacts with Tissues:

  • Semantic Discovery: An AI agent can scan the reactive graph for any collection tagged with Context.compliance.contains('GDPR').
  • Natural Language Mutators: AI can safely interact with a collection through a Deputy that enforces strict TestRules, ensuring the agent cannot break business invariants.
  • Automated Auditing: AI auditors can verify that sensitive data in a TissueMap is correctly redacted via FilterRules before it reaches public UI synapses.

Architecture Deep Dive

Conactive Atomic Execution

Mutations in a Tissue are "Conactive"—merging concurrent safety with reactive propagation. Every operation (add, remove, etc.) is wrapped in a dedicated synchronization lock. This ensures that the collection remains in a consistent state even when multiple reactive branches attempt to update it simultaneously.

Flyweight Sparse Records

To support massive-scale applications, we utilize Sparse Records for the Nucleus. This pattern avoids the overhead of nullable fields by using bitmask-driven property resolution. Property lookups (receptor, testRule) traverse a prototype chain, allowing deputies to override specific behaviors while inheriting the rest from the principal.

Collection Species

  • TissueList: The reactive backbone for ordered data. Supports growable and fixed-length variants.
  • TissueSet: Ensures uniqueness through reactive identity or equality checks.
  • TissueMap: Reactive key-value pairs where both keys and values can participate in the reactive graph.
  • TissueQueue: Optimized for FIFO/LIFO reactive pulse processing.
  • TissueValue: A "single-cell" tissue for managing a single reactive pointer or configuration.

Usage Examples

Basic Reactive Tissue

// A self-validating reactive list of IDs
final userIds = TissueList<int>(
  [101, 102],
  testRule: TestTissue.create(
    elementAllow: (id, _) => id > 0,
    maxLength: 100,
  ),
);

// Listen to structural changes
Cell.listen(
  bind: userIds,
  listen: (pulse) => print("Tissue update: ${pulse.soma}"),
);

userIds.add(103); // Emits a granular 'elementAdded' pulse

Composing Security Layers

// Base collection
final sensitiveData = TissueMap<String, String>({});

// Secure deputy for non-admin users
final publicView = sensitiveData.deputy(
  testRule: TestTissue.readOnly(),
  context: Context.user,
);

Performance & Scalability

  • O(1) Identity: deputy == principal is always true, enabling fast lookups in hash-based structures.
  • Lazy Resolution: Validation and pulse processing are only computed when needed.
  • Shared Storage: Deputies pointing to the same principal share the underlying Box, minimizing GC pressure.

Installation

Add cell_tissue and cell.core to your pubspec.yaml:

dependencies:
  cell.core: ^latest
  cell_tissue: ^latest
