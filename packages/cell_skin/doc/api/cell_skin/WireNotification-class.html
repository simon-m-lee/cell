WireNotification

WireNotification class final

A fire-and-forget signal used for environmental pings and lightweight updates.

In the framework's biological metaphor, WireNotification is a Transient Impulse. Unlike a WireResponse, it does not conclude a Command Journey, and unlike a WireStateChange, it does not represent a permanent Somatic State Transition. It is a temporary signal that leaves no trace in the Forensic Ledger.

When to use

  • Pings & Heartbeats: Use this to check if the Skin Membrane is alive.
  • Lightweight Alerts: Use this for non-critical information that doesn't require forensic integrity (e.g., "AI agent is thinking...").
  • Protocol Signaling: Used for MCP notifications or SSE metadata that falls outside the somatic graph.

How it works

  • Stateless: Notifications never carry a correlationId or a sequence number. They are emitted and forgotten.
  • Volatile: Because they are not ledgered, notifications are lost if the recipient is not listening at the exact moment the impulse occurs.

Non‑obvious behavior

  • Forensic Holes: Notifications are intentionally excluded from the Forensic Ledger. Never use them to transmit data that requires auditability or causal traceability.
  • Membrane Only: These signals exist only at the Skin layer. They never reach the core reactive graph or trigger internal cell updates.

See also

  • WireMessage: The base class for all signals crossing the membrane.
  • WireStateChange: For observations that represent actual state changes.

AI Agent Guide

Layer: Skin — this is a volatile signal. Constraint: Do not use for important data; notifications are not ledgered. Comparison: Use WireResponse for results and WireStateChange for values.
