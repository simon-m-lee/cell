RemoteCellClient

RemoteCellClient class final

A local handle representing a distant somatic entity behind a remote membrane.

In the framework's biological metaphor, RemoteCellClient is a Synaptic Projection. It acts as an Axon extending from the local environment to a cell physically located behind a remote Skin Membrane.

It provides a cell-like interface for triggering Somatic State Transitions on a target that exists in a separate somatic cluster, abstracting away the underlying transport (REST, MCP, or in-process bridge).

When to use

  • Cross-Cluster Interaction: Use this to mutate or observe cells hosted on a different server, AI agent, or process.
  • Orchestration: Ideal for building distributed somatic systems where one "brain" needs to stimulate "muscles" in a remote limb.

How it works

  1. Signal Packaging: Local calls are converted into Nervous Signals (WireRequest) containing the Skin Payload.
  2. Axonal Transport: The signal travels across the transport seam.
  3. Forensic Resolution: The client awaits a Forensic Receipt (WireResponse) to confirm the transition was anchored in the remote Forensic Ledger.

Non‑obvious behavior

  • Causal Linkage: The client automatically propagates lastSeenSeq markers. This ensures that the Command Journey maintains forensic integrity even across network boundaries.
  • Idempotency: Every impulse is stamped with a unique Causal Link (correlation ID) to prevent duplicate transitions if the transport layer retries the signal.
  • Observation: Calling observe creates a subscription to the remote cell's External Echo, allowing the local system to react to distant state changes.

See also

  • SkinClient: The coordinator usually responsible for spawning these handles.
  • WireRequest: The envelope used to stimulate the remote cell.
  • RemoteCellClient.inProcess: For simulating remote axons within the same memory space.
