WireStateChange

WireStateChange class final HowTo · Egress

An outbound state observation: a target cell's value changed.

Egress is not a reply — it carries no correlation id and can never complete a pending request().

When to use

  • Pushing state changes to observers: SSE /skin/observe/:cellId, MCP notifications, and SkinClient.observe.

How it works

With a bound ledger, egress is driven by Ledger.tail: the entry's own receipt pairs with the entry's own pulse payload (taken from the entry's canonical stored JSON). Without a ledger, target observations are always pendingReceipt — a receipt is never fabricated and never borrowed from an earlier change.

Non-obvious

pendingReceipt on a ledgered change is always false; on an unledgered change it is always true. There is no in-between state where a guess is presented as authoritative.

See also

wireStateChangeForEntry, SkinMembrane.responses, WireLedgerEntry.

AI Agent Guide

Layer: Skin — this is an observation, not a command reply. When to use: streaming target state changes to observers (SSE, MCP notifications, Dart clients). When NOT to use: completing a request — it has no correlation id; replies are WireResponse or WireError. Live signature: const WireStateChange({required String cellId, Object? payload, WireReceipt? receipt, bool pendingReceipt = false}) — pinned at cell_skin: 0.1.0 Do NOT confuse with: WireResponse.pendingReceipt (an accepted pulse whose entry is pending), or WireLedgerEntry (the audit row itself). Guide: ARCHITECTURE-Skin.md §4 (receipt provenance). Example: example/lib/widgets/home_pane.dart (the thermostat readout observes this variant). Cross-layer: the payload is the cell's value — its meaning belongs to the domain cell, not the skin. Minimal compilable example

final change = WireStateChange(
  cellId: 'home.living.thermostat',
  payload: 21,
  pendingReceipt: true, // no ledger bound — no receipt exists
);
