positional

positional property

Map<String, Object?>? positional
final

The data passed by position, stored as a string-keyed map for JSON safety.

In the framework's biological metaphor, these are the Numbered Nutrients of the Nervous Signal. They provide the raw data required by the target function in a specific order.

When to use

  • Ordered Arguments: Use this when the function you are calling expects arguments in a specific sequence (e.g., (name, age)).
  • Standard Tooling: Used by most MCP and REST bridges to pass primary data values.

How it works

  1. Index Mapping: Arguments are stored using their index as a string key (e.g., {"0": "Simon", "1": 30}).
  2. Unpacking: When the signal enters the cell, the framework converts this map back into a list to execute the internal logic.

Non‑obvious behavior

  • JSON Stability: We use a map {"0": ...} instead of a standard JSON list [...] because some network parsers and AI models accidentally reorder list items. Using string keys ensures the Command Journey stays accurate.
  • Forensic Recording: These values are recorded in the Forensic Ledger, allowing an auditor to see the exact data that triggered a Somatic State Transition.

Example

// For a function like updateTemperature(double value)
positional: {'0': 22.5}

See also:

  • WireRequest.named: For data passed using specific labels.
