lastSeenSeq

lastSeenSeq property

int? lastSeenSeq
final

The sequence number of the last entry the caller saw in the Forensic Ledger.

In the framework's biological metaphor, this is the Forensic Sync Marker. It acts as a somatic cursor, telling the system exactly which version of the cell's "DNA" the caller was looking at when they sent the signal.

When to use

  • Strict Synchronization: Use this when your application requires a "Strict Cursor" to prevent updates based on old data.
  • Data Integrity: Required for specific cell bindings to ensure that the caller is in sync with the latest Somatic State Transition.

How it works

  1. Sequence Check: When the WireRequest hits the membrane, the system compares this number to the current ledger sequence.
  2. Integrity Gate: If the numbers do not match (meaning the caller is out of sync), the Integrity Gate blocks the command.
  3. Rejection: The system returns a WireError so the caller knows they must refresh their state before trying again.

Non‑obvious behavior

  • Stale Update Prevention: This field is the primary defense against "Race Conditions." It ensures a request doesn't accidentally overwrite changes that happened while the signal was traveling over the wire.
  • Stateless Nature: Even if the transport layer (like REST) is stateless, this marker provides a stateful guarantee for the Command Journey.
  • Forensic Traceability: The ledger records this sequence to prove that the caller was correctly synchronized at the time of the action.

See also

  • WireLedgerEntry: The envelope that carries these sequence numbers.
  • ApplyOutcome: How the system reports if a cursor check failed.
