named

named property

Map<String, Object?>? named
final

The data passed by name, allowing for tagged arguments.

In the framework's biological metaphor, these are the Labeled Nutrients of the Nervous Signal. Unlike numbered arguments, these provide data using specific tags that the target function recognizes.

When to use

  • Tagged Arguments: Use this when the function you are calling expects data with specific names (e.g., updateProfile(name: 'Simon')).
  • Optional Data: Often used for optional settings or flags where the order of the data does not matter.

How it works

  1. Signal Tagging: The client provides a map where each key is a string matching a parameter name in the cell's function.
  2. Integrity Check: The system verifies these tags against the cell's Integrity Gate to ensure they are valid.
  3. Execution: The framework passes these values as named arguments when the Command Journey begins.

Non‑obvious behavior

  • Forensic Visibility: Every named argument is recorded in the Forensic Ledger. This allows auditors to see exactly which labeled signals caused a Somatic State Transition.
  • Safety: If you provide a name that the cell does not recognize, the request will be rejected at the membrane before it can change any internal state.

Example

// For a function like setStatus({required bool active})
named: {'active': true}

See also:

  • WireRequest.positional: For data passed by specific number/order.
