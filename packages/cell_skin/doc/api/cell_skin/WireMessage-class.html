WireMessage

WireMessage class sealed HowTo · Wire Messages Features

The universal envelope for every signal crossing the system's membrane.

In the framework's biological metaphor, WireMessage is the Skin Payload. Every Nervous Signal (Pulse) that enters or leaves the system must be wrapped in this envelope so it can safely travel over the network (the "Wire") via MCP, REST, or SSE.

When to use

  • Transport Adapters: Use this when writing code that talks to the outside world (like a web server or a command-line tool).
  • Membrane Crossing: Use this whenever a signal needs to move from the internal reactive graph to an external client.

How it works

  • Sealed Vocabulary: This is a closed (sealed) hierarchy. Every message has a specific kind (like request, response, or error).
  • Clean Serialization: The toJson method converts the message into a clean format for sending over the network.
  • Self-Identifying: The WireMessage.fromJson factory uses the kind field to automatically turn raw JSON back into the correct message type.

Non‑obvious behavior

  • Causal Matching: For requests and responses, the framework uses a correlationId to ensure the Forensic Receipt is matched to the correct original request.
  • Forensic Separation: A WireError represents a failure in the Skin (like a bad network connection) and never carries a Forensic Receipt, while a WireResponse carries the official result from the ledger.
  • Stateless Metadata: Metadata about the signal (like its timestamp) travels on the Pulse itself, not inside the WireMessage data.

See also

  • SkinPulseTypes: The taxonomy of labels used for these messages.
  • WireRequest: The envelope for incoming commands.
  • WireResponse: The envelope for outgoing forensic results.
