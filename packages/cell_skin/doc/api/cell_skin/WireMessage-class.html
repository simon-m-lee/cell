WireMessage

WireMessage class sealed HowTo · Wire Messages Features

One wire event. Every transport — MCP, REST, SSE, stdio — is a Pulse<WireMessage> whose type discriminates the variant.

When to use

  • Emitting or receiving commands, outcomes, state observations, and audit entries across the membrane.
  • Writing a transport adapter: the sealed hierarchy is the whole wire vocabulary — there is no other envelope.

How it works

Each variant carries exactly one intent; toJson produces the sanitised wire form and WireMessage.fromJson restores it. correlationId is server-assigned on requests; egress (WireStateChange) deliberately carries no correlation id.

Non-obvious

WireResponse and WireError look alike at a glance, but an error has no receipt — it must never masquerade as a response. Egress is WireStateChange, never a WireResponse.

See also

WireOutcome, WireReceipt, and SkinPulseTypes for the type taxonomy.
