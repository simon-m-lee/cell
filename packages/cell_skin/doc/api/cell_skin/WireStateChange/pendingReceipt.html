pendingReceipt

pendingReceipt property

bool pendingReceipt
final

Whether the permanent record for this change is still being written to the ledger.

In the framework’s biological metaphor, this indicates a Signal in Transit. It means the Somatic State Transition has occurred in the living cell, but the event has not yet landed in the Forensic Ledger.

When to use

  • Optimistic UI: Use this to show a "pending" or "live" state in your application while waiting for the authoritative proof.
  • Forensic Integrity: Check this to determine if the current observation is a finalized part of the system's "DNA" or a volatile impulse.

How it works

  1. Immediate Broadcast: If a cell is not backed by a ledger, or if the ledger write is asynchronous, this signal is sent immediately with pendingReceipt = true.
  2. Finalization: Once the Forensic Ledger confirms the write, a subsequent signal (or a WireLedgerEntry) is typically sent with pendingReceipt = false.

Non‑obvious behavior

  • Forensic Holes: If this is true, the state change is "unconfirmed." If the system crashes before the ledger write completes, this change may be lost, creating a gap in the forensic history.
  • Receipt Stale-ness: When this is true, the receipt field often contains the previous authoritative receipt, providing the last known stable context for the cell before this new transition.
  • Authoritative Default: In a system with a synchronous ledger, this field will almost always be false by the time the signal reaches the Skin Membrane.

See also

  • WireStateChange.receipt: The forensic proof that eventually clears the pending status.
  • WireLedgerEntry: The complete, non-pending audit record.
