Converts the notification into a JSON-safe map for transport.

In the framework's biological metaphor, this method creates the Skin Form of the impulse. It prepares the Transient Impulse to cross the Skin Membrane so it can be broadcast to the environment.

When to use

  • Egress: Use this when a server, MCP host, or SSE bridge needs to serialize a fire-and-forget signal for external subscribers.
  • Persistence: Used to store a snapshot of a notification in transport-level logs, though it will never appear in the core ledger.

How it works

  1. Signal Labeling: It includes the kind ('notification') so the receiver knows this is a volatile signal, not a response or state change.
  2. Intent Mapping: It embeds the method name to identify the type of impulse (e.g., a heartbeat).
  3. Nutrient Bundling: It attaches the params map containing the temporary data associated with the event.

Non-obvious behavior

  • Forensic Omission: The resulting map is intentionally excluded from the Forensic Ledger. It does not contain a correlation ID or a sequence number, as it represents "environmental noise."
  • Membrane Only: This transformation is strictly for the Skin layer. The data here never triggers a Somatic State Transition in the core reactive graph.
  • Stability: Like all wire messages, the output is a standard string-keyed map, ensuring compatibility with MCP and REST bridges.

See also

  • WireNotification.fromJson: The reverse process for decoding impulses.
  • WireMessage.kind: The base definition for the signal label.

Implementation

@override
Map<String, Object?> toJson() =>
    withWire({'kind': kind, 'method': method, 'params': params});
