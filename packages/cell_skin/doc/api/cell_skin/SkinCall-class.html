SkinCall

SkinCall class final

The ambient context of one membrane apply.

When to use

A domain TestCell.action reads SkinCall.current (or the PulseContext carried here) to see who is driving the apply before the function body runs. A binding body may read it too. The value is null outside a membrane apply.

How it works

The router wraps the target apply in SkinCall.run — inside the ledger scope when the router opens one. Zone.fork keeps parent zone values it does not override, so the LedgerScope survives when the caller already entered graph.run.

Non-obvious

Replay reconstructs the stored pulse and routes it through the receptor; it does not enter a SkinCall zone. A gate that decides only by reading SkinCall.current sees null on replay — the stored actor is the audit record. Gates that must keep refusing on replay keep checking the value (ValueGate, a door gate on the pulse payload).

AI Agent Guide

Layer: Skin — this is the "who called" zone, not an authorization decision. When to use: a domain gate must know the caller during apply; a binding must read the caller after an await. When NOT to use: replay-time authorization — replay does not enter this zone; stored actors are the audit record.
