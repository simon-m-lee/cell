A state binding: the user function returns the next value (or a Future of it, or a Pulse) and must not call update itself.

The binding wraps the returned value in a Pulse and routes it through the target receptor, so the only ledger row is the one Cell.apply records from that pulse — the wire receipt id and the ledger row's receipt id are the same. This is the shape the quick start should use for ledgered state changes.

nextValue stays the stored function; the wrapper exists only inside the ApplyCommand, so a debugger still shows the real closure. compensation is wrapped the same way, so an undo that returns the restored value becomes one pulse on compensationCell (or target).
