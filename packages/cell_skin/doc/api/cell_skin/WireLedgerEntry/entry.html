entry property

LedgerEntry entry
final

The technical forensic record containing the audit data.

In the framework's biological metaphor, this is the Forensic Record. It serves as a permanent segment of the system's "DNA," containing the sequence number, timestamp, and the Causal Link (correlation ID) that anchors a Somatic State Transition to the ledger.

When to use

  • History Reconstruction: Use this to build a sequence-perfect chronology of the system's state for auditing or time-travel debugging.
  • Verification: Use this to prove that a specific Command Journey was physically committed and to identify its global order relative to other impulses.

How it works

  1. Anchoring: After a cell passes an Integrity Gate, the Forensic Ledger assigns this record a unique global sequence number.
  2. Serialization: The ledgered data is converted into this record structure, preserving the metadata required for forensic analysis.
  3. Egress: The record is wrapped in a WireLedgerEntry and pushed through the Skin Membrane.

Non‑obvious behavior

  • Authoritative Truth: This is the only legal proof of a state change. Unlike the payload in a WireStateChange, the data here is guaranteed to be anchored in permanent storage.
  • Information Loss: As this is the Skin Form of the record, it does not contain live Dart object references. It contains only the values as they were physically encoded in the ledger.
  • Causal Linkage: The correlationId inside this entry allows auditors to map the resulting state change back to the original Nervous Signal (WireRequest) that triggered it.

See also

  • LedgerEntry: The internal forensic structure being carried.
  • WireLedgerEntry.kind: The label identifying this as a ledger signal.
