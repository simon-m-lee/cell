receiptJson

receiptJson property

Map<String, Object?>? receiptJson
final

A snapshot of the last known state of the ledger receipt for this cell.

In the framework's biological metaphor, this is the Somatic Snapshot. It provides a "best-effort" look at the cell's physical standing while the official Forensic Receipt is still being written to the ledger.

When to use

  • Pending Feedback: Use this when pendingReceipt is true to provide the caller with immediate, albeit unconfirmed, state data.
  • Synchronization: Helpful for clients to determine if they need to re-fetch the full state after a Command Journey completes.

How it works

  1. Capture: If a receipt is available (even if it belongs to a previous change or is currently being staged), it is serialized into this map.
  2. Verification: Once the ledger write is final, the authoritative WireLedgerEntry will contain the verified version of this data.

Non‑obvious behavior

  • Nullability: This field is null if no receipt has ever been seen for the target cell (e.g., a brand new cell that has never been physically committed).
  • Unconfirmed Data: When pendingReceipt is true, the data here is not yet legally part of the Forensic Ledger. It should be treated as a "guess" until the ledger sequence is assigned.
  • Stale State: In rare race conditions, this could reflect a state slightly older than the current impulse if the somatic anchoring hasn't updated yet.

See also

  • WireResponse.pendingReceipt: The flag indicating if this snapshot is still unconfirmed.
  • WireReceipt: The internal structure represented by this JSON map.
