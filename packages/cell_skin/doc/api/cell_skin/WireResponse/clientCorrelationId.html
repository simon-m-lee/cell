clientCorrelationId

clientCorrelationId property

String? clientCorrelationId
final

An optional ID provided by the caller to help them identify the response on their end.

In the framework’s biological metaphor, this is an External Echo. It acts as a private label placed on the Nervous Signal by the caller. The system carries this label throughout the Command Journey and returns it untouched in this response.

When to use

  • Client-Side Tracking: Use this if your client application needs to match an incoming response to a specific local action or UI update.
  • Async Coordination: Helpful when a client sends many requests at once and needs to know which one just finished.

How it works

  1. Signal Tagging: The client provides this string when the WireRequest is first sent.
  2. Passthrough: The system ignores this field for its internal governance but keeps it attached to the signal.
  3. Reflection: When the final Forensic Receipt (WireResponse) is generated, this ID is copied back into the envelope.

Non‑obvious behavior

  • No Internal Authority: The system never uses this field for internal matching, security, or state logic. The correlationId remains the only "Source of Truth" for the Forensic Ledger.
  • Verbatim Echo: The framework returns this string exactly as it was received, even if the request was rejected by an Integrity Gate.
  • Optional: If this field is left empty in the request, it will be null here.

See also

  • WireRequest.clientCorrelationId: Where this label is first applied.
  • WireResponse.correlationId: The authoritative ID used by the server.
