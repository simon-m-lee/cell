pendingReceipt

pendingReceipt property

bool pendingReceipt
final

Whether the permanent record for this change is still being written to the ledger.

In the framework’s biological metaphor, this indicates a Signal in Transit. It means the Nervous Signal was accepted by the cell, but the Somatic State Transition has not yet finished landing in the Forensic Ledger.

When to use

  • Optimistic UI: Use this to show a "pending" or "sending" state in your application while waiting for the final authoritative proof.
  • Forensic Integrity: Check this to determine if the provided outcome is final or if a later confirmation is expected.

How it works

  1. Signal Acceptance: The cell processes the command and returns an immediate result.
  2. Ledger Staging: If the ledger write is asynchronous, the system sets this field to true.
  3. Finalization: Once the write is complete, a separate WireLedgerEntry is typically sent to confirm the permanent sequence.

Non‑obvious behavior

  • Forensic Holes: If this is true, the outcome provided is a "best guess" based on the current impulse. The final, authoritative proof only exists once it is assigned a sequence number in the ledger.
  • Authoritative Conflict: If a network error occurs while this is true, the client must treat the state as "uncertain" until the Forensic Ledger can be resynchronized.
  • Default State: In a standard authoritative response, this is false, meaning the change is already physically committed.

See also

  • WireResponse.receiptJson: A snapshot of the state while the receipt is pending.
  • WireLedgerEntry: The envelope that carries the final, non-pending confirmation.
