Creates a new WireResponse envelope to carry a result back through the membrane.

In the framework’s biological metaphor, this constructor assembles the Forensic Receipt. It marks the end of a Command Journey and provides the proof needed to satisfy the caller's initial Nervous Signal.

When to use

  • Completing a Request: Use this when a cell has finished processing an apply command and you need to send the ApplyOutcome back to the originating transport (MCP, REST, etc.).
  • Testing: Use this to simulate authoritative or pending responses in integration tests.

How it works

The constructor bundles the outcome of the state transition with causal metadata. It enforces a strict Integrity Guard via an assertion: a response must either be a placeholder for a ledger write in progress (pendingReceipt), or it must contain a concrete result (outcome or outcomeJson).

Parameters

  • correlationId: The authoritative Causal Link used to pair this receipt with the original request.
  • clientCorrelationId: The External Echo provided by the caller.
  • outcome: The Live Forensic Receipt generated by the cell (used for internal/Dart-native responses).
  • outcomeJson: The Skin Form of the result (used for responses decoded from the wire).
  • pendingReceipt: Indicates if the Somatic State Transition is still being written to the Forensic Ledger.
  • receiptJson: A Somatic Snapshot of the ledger state, providing immediate context while a receipt is pending.

Non‑obvious behavior

  • Authoritative Invariant: You cannot create a non-pending response without providing an outcome. This prevents "Forensic Holes" where a command appears to finish without leaving a trace or result.
  • Mutual Exclusivity: While the constructor allows both, typically either outcome (live) or outcomeJson (wire) is used, depending on which side of the Skin Membrane the code is running.
