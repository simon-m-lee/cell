WireResponse

WireResponse class final

An envelope for an outbound result: the official response to a request.

In the framework's biological metaphor, WireResponse is the Forensic Receipt delivered to the Skin Membrane. It proves that a Nervous Signal completed its Command Journey and reports whether it was accepted or rejected by the system's DNA.

When to use

  • Request Completion: Use this as the standard reply to a WireRequest.
  • Transport Mapping: Use this to send the results of a command back to a web client (REST) or an AI agent (MCP).

How it works

  1. Signal Outcome: The system takes the ApplyOutcome from the internal cell and packages it into this envelope.
  2. Correlation: It attaches the correlationId so the caller can match this receipt to their original request.
  3. Ledger Synchronization: If the framework is still writing the result to the permanent log, the response is marked as pendingReceipt.

Non‑obvious behavior

  • Serialization Guard: A live ApplyOutcome contains functions and complex logic that cannot be sent over the wire. Therefore, decoded responses store the result as outcomeJson instead.
  • Definitive Receipts: If pendingReceipt is true, the outcome provided is a "best guess." The final, authoritative proof only arrives later via the Forensic Ledger stream.
  • Authoritative Outcome: A WireResponse never reports transport failures (like a lost connection); those are handled by WireError. This class only reports the cell's actual logic results.
