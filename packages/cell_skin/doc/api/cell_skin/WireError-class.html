WireError

WireError class final HowTo · Wire Messages

A failure signal indicating that a request was rejected before reaching the core graph.

In the framework's biological metaphor, WireError is a Membrane Rejection. It represents a Nervous Signal that was stopped at the Skin Membrane or blocked by an Integrity Gate before a Command Journey could begin.

Because the signal never reached a cell's apply logic, no Forensic Receipt is generated, and no Somatic State Transition occurs. If this error is not reported to the caller, it creates a Forensic Hole in the system's external observability, as there is no entry in the Forensic Ledger to explain the missing state change.

When to use

  • Transport Failures: Use this for network errors or protocol violations (transport_error).
  • Exposure Rejections: Use this when a tool is unknown (unknown_tool) or arguments fail basic schema validation at the membrane (bad_arguments).
  • Conflict/Cursor Errors: Use this when a request is rejected due to concurrency or missing prerequisites (conflict, cursor_required).

How it works

  1. Signal Ingress: A request hits the Skin Membrane.
  2. Validation Failure: The router or adapter identifies a problem before the command can be dispatched to a cell.
  3. Rejection: Instead of a WireResponse, this envelope is returned to explain why the ledger remains unchanged.

Non‑obvious behavior

  • Forensic Omission: This error is not written to the Forensic Ledger. It is a transient signal about a failed attempt to change state.
  • Receipt Absence: Unlike domain-level rejections (which produce an ApplyRejected outcome in a WireResponse), this variant exists specifically to signal that no receipt was ever created.
  • Security: The message field is sanitized to avoid echoing raw internal exception details, preventing information leaks about the system "DNA."

See also

  • WireResponse: For rejections that happen inside the cell's logic.
  • SkinRouter: The component usually responsible for generating these errors.
