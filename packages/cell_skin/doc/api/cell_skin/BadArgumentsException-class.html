BadArgumentsException

BadArgumentsException class final

An exception thrown when a Nervous Signal contains a malformed Skin Payload.

In the framework's biological metaphor, BadArgumentsException represents a Membrane Rejection triggered by structural inconsistencies in the incoming data. It occurs at the Skin Membrane before a Command Journey can be initiated.

Because this exception is caught during the transformation of the WireRequest into an ApplyCommand, no Somatic State Transition is attempted, and no Forensic Receipt is generated in the Forensic Ledger.

When to use

  • Structural Violations: Automatically thrown by SkinBinding when positional argument keys are not a contiguous 0..n-1 range.
  • Identifier Violations: Thrown when named argument keys fail basic Dart identifier validation (e.g., containing dots or invalid characters).

How it works

  1. Signal Ingress: A WireRequest arrives at the membrane.
  2. Payload Analysis: The SkinBinding attempts to decode the positional and named arguments into their internal somatic forms.
  3. Gate Failure: If the keys are malformed or non-contiguous, this exception is raised.
  4. Rejection: The SkinRouter catches the exception and returns a bad_arguments WireError to the caller.

Non‑obvious behavior

  • Forensic Omission: This failure is a membrane-level event. Since the pulse never reached the target cell's apply logic, it leaves a "Forensic Hole" where the caller sees a failure but the ledger remains silent.
  • Pre-Gate Validation: This check happens before any JsonSchema validation or cell-specific Integrity Gate logic.

See also

  • WireError: The envelope returned when this exception occurs.
  • SkinBinding.toApplyCommand: The method responsible for triggering this validation.
