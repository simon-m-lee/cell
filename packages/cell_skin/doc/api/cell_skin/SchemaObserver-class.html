SchemaObserver

SchemaObserver class final

The collector responsible for learning the system's DNA by watching signals.

In the framework's biological metaphor, SchemaObserver is the Somatic Watcher. It sits at the Skin Membrane and records every Nervous Signal (impulse) that successfully triggers a Somatic State Transition, using them to build a cumulative Somatic Blueprint of what the system accepts.

When to use

  • Automatic Discovery: Use this to dynamically populate the Somatic Index (manifest) without requiring manual schema definitions.
  • AI Adaptation: Allows the system to "learn" the shape of valid tool calls by observing real-world usage in the Forensic Ledger.

How it works

  1. Signal Capture: Every time a cell's apply logic is triggered, the observer is notified of the Somatic Nutrients (arguments).
  2. Trait Induction: It uses schemaForValue to derive the immediate DNA shape of those nutrients.
  3. DNA Synthesis: It uses mergeSchemas to widen its internal blueprints, ensuring the resulting schema represents the union of all valid signals seen so far.

Non‑obvious behavior

  • Cumulative Memory: The observer never "forgets" a valid shape. Once a trait is induced and merged, the schema remains wide enough to accept that shape forever, preventing "Forensic Holes" where previously valid signals suddenly fail.
  • Stability: The resulting namedSchemas and positionalSchemas are sorted and unmodifiable, ensuring the Skin Form of the manifest remains deterministic for external AI agents.
  • Thread Safety: Designed to be used within a single somatic governance loop; external access is provided via read-only views.

See also

  • JsonSchema: The blueprint being accumulated.
  • schemaForValue: The induction logic used for each observation.
  • mergeSchemas: The synthesis logic used to grow the DNA.
