WireOutcome

WireOutcome class final

The wire-safe JSON read model of a cell's application result.

In the framework's biological metaphor, WireOutcome is the Skin Form of the Forensic Receipt. While the internal framework uses ApplyOutcome to handle live objects and functions, this class represents the sanitized version that is safe to transmit across the Skin Membrane.

When to use

  • Remote Inspection: Use this on the client side (AI agent, web app) to verify the result of a Command Journey.
  • Serialization Boundary: The primary structure used when converting a Somatic State Transition result into a JSON payload.

How it works

  1. Sanitization: During encoding, the system checks if the result or reason can be encoded as JSON.
  2. Omission Guard: If a value is not serializable, it is replaced with a placeholder to prevent a transport failure (a "Forensic Hole"), and the corresponding omitted flag is set to true.
  3. Forensic Integrity: The receipt field carries the technical metadata (sequence, timestamp) required to anchor the result in the Forensic Ledger.

Non‑obvious behavior

  • Read-Only: This is a "honest" JSON model. It does not attempt to reconstruct live Dart functions or cell references, as those cannot physically survive the trip across the wire.
  • Authoritative Outcome: The kind property acts as the Signal Tag, telling the receiver if the transition was accepted, rejected (by an Integrity Gate), or staged.

See also

  • ApplyOutcome: The live, internal version of this result.
  • WireReceipt: The detailed forensic metadata attached to this outcome.
  • wireOutcomeJson: The utility that performs the sanitization and encoding.
