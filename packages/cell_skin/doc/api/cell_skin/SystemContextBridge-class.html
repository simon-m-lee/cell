SystemContextBridge

SystemContextBridge class final

A bridge that resolves every incoming signal's base context to Context.system.

In the framework's biological metaphor, SystemContextBridge is the Somatic Override. It ignores the specific traits of the external SkinPrincipal and stamps the Command Journey's base context with the system's own "DNA" (Context.system).

When to use

  • Trusted Automation: Use this for internal scripts, administrative tools, or trusted proxies where the Skin Membrane should not impose identity-based restrictions.
  • System-to-System Bridges: Ideal for linking two different cell clusters where the bridge itself is considered a part of the authorized nervous system.

How it works

  1. Signal Ingress: A WireRequest arrives.
  2. Base Elevation: The bridge ignores the credentials provided by SkinAuth and resolves to Context.system.
  3. Principal Still On Top: the request context's own actor remains skin:<principal id> (the REST adapter always stamps skinPulseContext), and the principal snapshot still rides in others['skin.principal']. A gate that reads only SkinCall.current!.pulseContext.actor sees the principal, not system; a gate that reads the base context sees Context.system.

Non‑obvious behavior

  • Does not skip the domain gate: a refusing TestCell still rejects the apply — system authority is provenance, not a bypass.
  • Forensic Visibility: The ledger row still carries the skin:<principal id> actor from the pulse the binding returned; the system base is part of the stored context lineage.
  • Security Risk: This bridge marks every request as system-based provenance. It should only be used over physically secured or highly trusted transport layers.
  • Authority Persistence: Any cell mutation triggered via this bridge carries the system base context.

See also

  • Context.system: The high-authority base context being granted.
  • DescribeContextBridge: A safer alternative that preserves external identity.
