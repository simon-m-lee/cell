CellListView

CellListView<T> class

A virtualized list whose item collection is bound to a Cell.

CellListView is the binding's Cell-Bound List — the ListView equivalent of CellBuilder for collections. It observes a cell that produces List<T> (a Cell.state<List<T>> result, a TissueList, a derived projection, an asyncMap result) and renders it as a lazy ListView.builder, so only visible items are laid out regardless of the list length.

Two constructors cover the two production patterns:

  • CellListView.builder — the naive variant. Every list change rebuilds the visible items through the normal ListView.builder reconciliation. Compose a per-item CellBuilder inside itemBuilder when each item has its own cell:

    CellListView<User>.builder(
  cell: users.cell,
  itemBuilder: (ctx, user, i) => CellBuilder<User>(
    cell: getUserCell(user.id),
    builder: (_, u) => ListTile(title: Text(u?.name ?? '')),
  ),
);

  • CellListView.keyed — the diffed variant. itemKey extracts a stable key per item; the list keeps a widget cache and only calls itemBuilder for items whose key is new. Items are wrapped in KeyedSubtree(ValueKey(itemKey)) and the list supplies findChildIndexCallback, so unchanged items preserve their element state (focus, scroll offsets, animations) across mutations and reorders. Duplicate keys throw StateError — keys must be unique within the list.

    Index freshness note: a cached item widget keeps the index it was built with. A reorder does not re-run itemBuilder, so widgets that render their own index show the index from their first build. Use CellListView.builder when index-fresh rendering matters more than rebuild avoidance.

Scroll position

The ListView element is preserved across list changes, so the scroll position survives mutations in both variants (subject to Flutter's usual ScrollController rules).

Known limitation (keyed variant)

The keyed variant builds a widget configuration per item up front (O(n) memory) and diffs in O(n) time per list change. This is the documented trade-off for not rebuilding unchanged items; for lists in the tens of thousands with per-item cells, prefer CellListView.builder with per-item CellBuilder composition.

Example

final todos = Cell.state<List<String>>(initial: ['a', 'b']);
CellListView<String>.builder(
  cell: todos.cell,
  itemBuilder: (ctx, todo, i) => ListTile(title: Text(todo)),
);
