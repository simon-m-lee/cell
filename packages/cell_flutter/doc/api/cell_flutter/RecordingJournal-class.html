RecordingJournal

RecordingJournal class

The recording side of the journal.

How it works

Every effect is executed for real; the journal records the observation and the run continues. The recorded log is what ReplayJournal consumes later.

Non-obvious: recording happens after the operation, not before

If the operation throws, there is no effect to record — the throw propagates and the ledger records the failure, not an effect. This is deliberate: a failed I/O call is not a re-runnable observation; the caller must decide whether to retry (in which case the retry is the new effect).

See also:

  • ReplayJournal — consumes this journal's log.
  • EffectJournal — the shared contract.
