CellErrorBoundary

CellErrorBoundary class

Renders a fallback instead of Flutter's error screen when a cell-driven error is thrown while building the subtree below it.

CellErrorBoundary is the binding's Error Boundary. It protects a subtree against the synchronous widget-lifecycle failures cells can cause:

  • a CellNotifier bound to an invalidated cell (thrown from CellBuilder / CellSelector / useCell* during initState);
  • a setState-during-build error triggered by a pulse arriving while a cell-driven widget is building.

When such an error is reported, the boundary renders onError instead of child; calling CellErrorBoundaryState.reset re-renders the child.

What the boundary does NOT intercept

Errors reported through the binding's report channel — FlutterError.reportError with library: 'cell_flutter' (type mismatches, emitErrors: true error pulses, CellListener handler failures) — are not captured: the reporting widget already handles them, and no exception was thrown. Those reports are forwarded to the previously installed FlutterError.onError. This boundary does not replace ErrorWidget.builder.

Nested boundaries

A captured error is consumed by the nearest boundary: the inner boundary shows its fallback and the outer one never sees the error. Reports on the cell_flutter channel pass through every boundary unchanged.

Known limitation

The interception is global (FlutterError.onError) while the boundary is mounted: a non-cell error thrown elsewhere in the app is attributed to the boundary if it arrives first. Use the boundary as a root safety net, not as fine-grained per-screen instrumentation.

Example

CellErrorBoundary(
  onError: (error, stack) => ErrorCard(error: error),
  child: CellBuilder<int>(
    cell: counter.cell,
    builder: (_, v) => Text('$v'),
  ),
);

See Also:

  • CellErrorBoundaryState.reset — the recovery entry point.
  • ErrorWidget.builder — the Flutter mechanism this complements.
