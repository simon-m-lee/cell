CellAsValue

CellAsValue extension

An extension that mirrors any Cell into a fresh ValueCell.

CellAsValue is the binding's Mirror Factory. Widgets that require a ValueCell — CellBuilder, CellSelector — cannot take a plain Cell (Cell.derive, Cell.synthesis, Cell.switchMap, async sources, cell_tissue collections). This extension bridges that gap: it opens a Cell.observe link on the source and re-emits the source's payloads into a brand-new ValueCell whose value can be read synchronously.

Why it is used

  • Bridge to ValueCell-only widgets: obtain a ValueCell from any Cell so CellBuilder / CellSelector can be used without changing their ValueCell requirement.
  • Service-layer mirrors: share a mirrored value across components that outlive any single widget, without routing through Flutter's lifecycle. The returned MirroredCell gives you explicit ownership of the mirror's lifetime.

How it works

  1. Create the mirror: a fresh ValueCell is created and seeded from the source's retained pulse (any state-like operator that already emitted, plus ValueCell's current value), or from the caller's initial if no visible value is available (see Seed semantics).
  2. Observe the source: a Cell.observe link is opened on the source and forwards each data pulse into the mirror's value setter, which broadcasts to the mirror's own observers.
  3. Return the handle: the mirror and the egress-stop callback are paired in a MirroredCell record.

Design Note: why a record and not just the ValueCell

Returning a bare ValueCell<V> would be a shorter signature but a worse contract. The mirror's backing egress is not observable from the ValueCell interface, so a caller who wanted to stop mirroring would have no way to do so. The MirroredCell record makes the disposal obligation part of the return type — you cannot obtain a mirror without receiving the way to release it.

Seed semantics (please read)

The mirror is seeded through retainedPulseOf, which reads the core package's retained pulse via Cell.latestPulse (covering fromFuture, fromStream, asyncMap, derive) and serves a ValueCell's current value as a fallback. A plain async cell that already emitted before the mirror was created is therefore seeded from its retained value, not from initial — a completed Cell.fromFuture mirrors 42 on the first read. initial is the fallback when the source has never emitted a visible data pulse. See test/seed_paths_test.dart for the coverage.

Error pulses

Error pulses from the source are silently skipped. Mirroring is a value-display operation; errors have no place in a ValueCell's value slot. If you need to observe errors, subscribe to the source directly (via Cell.observe, CellListener, or asStream(emitErrors: true)).

Type-mismatch payloads

A data pulse whose payload is not assignable to V is reported through Zone.current.handleUncaughtError with a StateError. This differs from the other bindings, which use FlutterError.reportError — the mirror is widget-independent, so it cannot assume a Flutter error reporter is installed. A type-mismatch is a caller bug: the source emits payloads of a type the mirror's V cannot hold.

Concurrent asyncMap caveat

If the source is Cell.asyncMap with concurrency > 0 (or overlapping latestOnly futures), the mirror inherits the framework's caveat: concurrent effect attribution is tracked separately and is not yet verified end-to-end. The mirror's observation is correct; the caveat is about the source's replay fidelity. See the cell core package for status.

Example

class MyService {
  late final MirroredCell<int> _mirror;

  MyService(Cell source) {
    _mirror = source.asValueCell<int>(initial: 0);
  }

  void dispose() => _mirror.dispose();

  ValueCell<int> get mirror => _mirror.cell;
}
