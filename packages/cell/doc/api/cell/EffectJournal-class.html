EffectJournal

EffectJournal class abstract

The boundary between a receptor and the outside world.

When to use

Every observation that is not a function of the receptor's inputs is routed through an EffectJournal. On the recording side, the journal captures each observation; on the replay side, it serves the recorded value instead of touching the outside world. The receptor code is identical in both cases — this is what makes replay exact.

Non-obvious: the journal is a stack, not a singleton

An outer transaction might record an effect, while an inner evaluation (e.g. a what-if branch) needs to be replayed from a different journal without disturbing the outer recording. JournalScope keeps a stack; EffectJournal.current returns the top of the stack. The stack is task-local (see JournalScope) — a Future spawned outside the scope does not inherit the journal, which is deliberate: a spawned task whose effects are not journalled is a bug we want to surface, not hide.

See also:

  • ReplayJournal — the replay side.
  • NullJournal — the loud sentinel for "no journal in scope".
