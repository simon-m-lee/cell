Record (or replay) an effectful TestCell verdict.

How it works

On the recording side, run is executed and its boolean decision is recorded as a VerdictEffect. On the replay side, the recorded decision is served and run is not executed — the rule is not re-called (purity dispatch).

Parameters:

  • ruleLabel: A stable label identifying the rule.
  • input: The object being tested; its fingerprint is recorded.
  • run: The closure that computes the verdict.
