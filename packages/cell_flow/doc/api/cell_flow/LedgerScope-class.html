LedgerScope

LedgerScope class

The graph-scoped ambient that coordinates state capture and ledger append.

When to use

LedgerScope is not per-pulse (that is JournalScope's role); it lives for the lifetime of a CellGraph's binding to a Ledger. It provides two functions:

  • captureDelta — called by ValueCell.postProcessRule when a cell commits a new value. Appends the delta to the current pulse's pending list. No-op if no Ledger is bound.
  • recordPulse — called by Cell.apply and the ValueCell emit path after the receptor has produced its output. Takes the pulse, the receipt, and the effects from the active JournalScope, combines them with the deltas captured during the pulse's processing, and calls Ledger.appendInternal.

Why the split

postProcessRule runs inside the receptor pipeline (it is the "postProcess" stage). It has access to (before, after) and to the cell's id, but not to the ApplyReceipt — the receipt is created by Cell.apply before the receptor runs. Conversely, Cell.apply has the receipt but cannot observe the delta (the receptor is opaque). The two halves must meet somewhere; LedgerScope is that meeting point.

Non-obvious: no scope means no ledger

If no LedgerScope is active (a cell used outside a CellGraph), captureDelta and recordPulse are silent no-ops. This is what keeps existing code working: the framework's default is not to record, and recording is an opt-in provided by CellGraph + Ledger. A user who wants auditable state binds a ledger; a user who does not, does not pay.

See also:

  • CellGraph.run — pushes a scope around a body of work.
  • JournalScope — the per-pulse stack this scope coordinates with.

Static Methods

captureDelta(StateDelta delta) → void
Capture a delta from ValueCell.postProcessRule. No-op if no scope is active.
captureEffect(EffectRecord record) → void
Hands an operator-recorded effect to the current scope. The effect is attributed to the pending pulse window; the append at window close carries it in the entry's effects list.
recordPulse({required Pulse pulse, ApplyReceipt? receipt, Cell? emitCell, Function? emitFunction, Object? emittedValue}) → void
Records a completed pulse through the active scope (if any). When no receipt exists (the direct ValueCell emit path), a synthetic receipt is produced from emitCell and emitFunction. The caller remains synchronous: the append is queued on the scope's serialisation chain and drained when the enclosing run completes.
recordPulseDeferred({required Pulse pulse, ApplyReceipt? receipt, Cell? emitCell, Function? emitFunction, Object? emittedValue}) → void
Records a pulse whose observable settlement happens asynchronously (ingress emits whose downstream operators perform effects in detached continuations). The entry is appended one event-loop turn later — after the microtask queue settles, and with it the operator's cooperative captureEffect calls — so the entry carries the effects and deltas the pulse actually produced.
run<T>(LedgerScopeImpl scope, FutureOr<T> body()) → Future<T>
Runs body with scope pushed. Pops on exit (success or error), and drains the scope's queued appends before returning so a synchronous body that performed ValueCell.updates has its entries committed by the time this resolves.
runSync<T>(LedgerScopeImpl scope, T body()) → T
The synchronous variant. Used by ValueCell.postProcessRule, which is synchronous.
