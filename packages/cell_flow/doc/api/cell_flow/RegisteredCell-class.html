RegisteredCell

RegisteredCell class

A thin wrapper that pairs a Cell with its graph-scoped name.

When to use

As the handle that CellGraphBuilder.register returns. It is not a Cell itself — it is a handle that lets callers carry the registered name alongside the cell, e.g. to pass into a CellGraphSnapshot constructor without re-looking up the name from the registry.

How it works

The distinction matters because Cell.id already resolves the name from the registry; the wrapper exists so that some call sites (like CellGraph.register) need not trust the registry. Outside the graph construction path, cell.id is the canonical accessor and the wrapper is not needed.

Non-obvious: the wrapper does not replace the cell

A RegisteredCell is not a deputy. It shares no state with the wrapped cell (there is no state in the wrapper). It is purely a (cell, name) pair. Passing a RegisteredCell where a Cell is expected requires calling .cell. This is deliberate — the compiler is the enforcement that a registered cell and a raw cell are not interchangeable, which is what makes the "unregistered bind rejected" check possible without heuristics.

See also:

  • CellGraphBuilder — produces these wrappers.
  • CellGraphSnapshot — consumes the registered name.
