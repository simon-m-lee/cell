ContextTranslator

ContextTranslator class abstract

Bridges a DeputyContext across mandate schema versions.

When to use

A ContextTranslator is the user's hook for "the mandate schema changed between version A and version B — here's how to translate a version-A context into a version-B context". The framework cannot know what fields were added, renamed, or deprecated; it only knows that a version boundary exists and must be crossed.

Non-obvious: a translator is directional

v1 → v2 is not the same as v2 → v1. Replay only ever goes forward (the ledger records the past; the graph is the present). If a ledger recorded a version-2 context and the current graph is version-1 (a downgrade), the translator for v2 → v1 is required — but a downgrade is almost always a semantic loss (a field added in v2 has no home in v1), and the framework cannot safely assume which direction preserves meaning. The ContextTranslator API therefore requires the caller to declare both the source and target versions explicitly.

See also:

  • ContextTranslatorRegistry — keyed (from, to) storage.
  • CellGraphTranslators — the per-graph registry accessor.
