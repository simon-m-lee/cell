Ledger

Ledger class

The durable, hash-chained record of every state transition.

When to use

A Ledger is bound to a CellGraph and a LedgerStore. It is the authoritative history of the graph; the graph's current state is a derived value that can be reconstructed by replaying the ledger from a snapshot.

Non-obvious: appendInternal is not called by users

"Append from inside a receptor is rejected" is a core invariant. The enforcement is: appendInternal is @internal and only invoked from _LedgerScopeImpl.recordAndAppend, which is pushed by Cell.apply and the ValueCell emit path (with the delta captured by postProcessRule). A user who calls appendInternal directly will hit the @internal warning in a strict analyzer config; more importantly, they will not have the delta and will produce an entry whose deltaDigest is fingerprint([]), which the engine's ReplayEngine rejects as a divergence at replay time. That is the correct outcome: the ledger is not a general-purpose journal, it is a coordinated record, and the coordination lives in LedgerScope.

See also:

  • LedgerStore — the persistence backend.
  • LedgerEntry — the rows this ledger holds.
  • HashChain — the hash chain that binds the rows.
  • ReplayEngine — replays this ledger into a graph.

open({required CellGraph graph, required LedgerStore store, String? genesisHash}) → Future<Ledger>
Creates a ledger bound to graph and backed by store. The genesis hash is fingerprint({'graphId': graph.id}); the store's own genesisHash must match, or this throws — a store created for graph G can never silently serve graph H.
