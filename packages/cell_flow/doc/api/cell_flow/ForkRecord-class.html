ForkRecord

ForkRecord class

The genesis record of a fork ledger.

How it works

A fork ledger's seq 0 is always a ForkRecord. It carries enough information for an auditor to answer three questions:

  • Where did the fork start? divergedAt is the parent ledger's sequence number at which the fork was taken.
  • What was the state at the fork point? originalSnapshotHash is the parent graph's snapshot hash at divergedAt. It binds the fork to a specific parent state, so two forks at the same atSeq with different snapshot hashes are distinguishable.
  • Which fork is this? forkId is a UUID; two forks of the same parent at the same atSeq get different ids.

Non-obvious: the fork record is not a LedgerEntry

It has a different shape and different verification rules (the genesis prevHash is not the graph's genesis hash, it is the fork record's own genesis hash; the hash is computed from the synthetic entry's fields by the fork ledger store). ForkLedgerStore presents the fork record as a synthetic seq-0 entry so Ledger.verify runs unmodified, and the fork's real entries chain from it.

See also:

  • ForkHandle — carries the record alongside the fork's graph and ledger.
  • ForkLedgerStore — materialises this record as seq 0.
