# mitose_flutter — the Flutter Mitose pipeline

Turns a structured BRD (`flutter-pipeline/v1`) into a verified Flutter
app built on cell_flutter. This package implements the Mitose pipeline:
parse the BRD, place every requirement with executable rules, walk the
human through the design, generate code + tests, verify with a
five-category rubric, and write the LEDGER.

This is an internal v0.1 pipeline (`publish_to: none`); the target is
`cell_flutter >=1.0.0 <2.0.0`.

## Quick start

```bash
# From this directory:
dart pub get

# Generate an app (auto-approves gates when non-interactive):
dart run bin/mitose_flutter.dart generate example/brds/form_heavy.bfd.md \
  --out ../your_app --no-gates

# Verify the generator against the committed references:
dart run bin/mitose_flutter.dart verify example/brds/form_heavy.bfd.md

# Assess an existing app tree:
dart run bin/mitose_flutter.dart assess example/brds/form_heavy.bfd.md \
  --app ../your_app
```

Exit codes: `0` success (or deliberate gate rejection), `1` pipeline
failure (schema, placement, rule, or assessment), `2` usage/unexpected.

## Contracts (docs/)

- `docs/brd-schema.md` / `docs/brd-schema.json` — the BRD format.
- `docs/pipeline-cli.md` — the CLI contract (commands, gates, flags,
  exit codes).
- `docs/placement-guide.md` — the 15 placement rules.
- `docs/rubric.md` — the five-category verification rubric.
- `docs/output-tree.md` — the generated tree (`flutter-pipeline/v1`).
- `docs/failure-modes.md` — the 18 documented failure modes with
  responsibilities.

## Layout

- `lib/src/brd/` — AST, schema validation, parser, walkthrough/design.
- `lib/src/rules/` — placement rules, patterns, anti-patterns.
- `lib/src/generator/` — code + test generators.
- `lib/src/rubric/`, `lib/src/ledger/` — assessment + LEDGER.
- `lib/src/cli/` — commands, gates, output writer.
- `example/brds/` — the three canonical BRDs.
- `example/generated/` — committed reference outputs (regenerated by
  `dart run tool/regenerate_references.dart`; `verify` byte-compares
  against them).

## Tests

```bash
dart test                                # fast, hermetic
PIPELINE_COMPILE=1 dart test \
  test/generator/compile_gate_test.dart  # generates + flutter-analyzes
                                         # + flutter-tests each app
```

## Reference regeneration

Generated apps are deterministic. When a generator change lands,
regenerate and commit the references together:

```bash
dart run tool/regenerate_references.dart
dart run bin/mitose_flutter.dart verify example/brds/form_heavy.bfd.md
dart run bin/mitose_flutter.dart verify example/brds/list_heavy.bfd.md
dart run bin/mitose_flutter.dart verify example/brds/async_heavy.bfd.md
```

## Scope notes (v0.1)

- Generated apps depend only on `cell_flutter` (no router/persistence
  packages); navigation is plain `Navigator` + `MaterialPageRoute`.
- `--schema=<path>` is accepted for contract compatibility; the
  embedded validator implements `flutter-pipeline/v1` natively.
- The rubric checks the generated tree statically and through the
  generated tests; pixel goldens, accessibility, and localization are
  out of scope (see `docs/rubric.md`).
