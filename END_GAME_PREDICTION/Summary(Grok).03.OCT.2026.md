**Synthesis of nine model assessments**

The nine follow-up notes agree on the facts and split on the weight. Mitose is a change of adoption strategy, not a new runtime. It makes agents builders of Mitosis before Mitosis is a runtime that governs agents.

## What the nine notes are answering

Claude, DeepSeek, Dola, Gemini, GLM, Grok, Kimi, OpenAI, and Qwen each revisited an end-game forecast written against the rc.5 line, after the repository added the Mitose pipeline: an agent-executed sequence from a business requirement to a Business Requirements Document, a WalkThrough, a human gate, a Demo, a reassessment, and optional ARCHITECTURE and FEATURES documents, triggered by “Mitose” in `AGENTS.md`. Sample BRDs cover baggage handling, assembly-line downtime, freight rail, and hospital emergency flow.

Runtime changes in the same window were small — a widened `Pulse.type`, a unified `TissueEvent`, an umbrella re-export. Replay, distributed cells, Flutter adapters, and a durable pulse trail did not ship. `cell_organ` was committed and withdrawn. External traction was unchanged: one author, no stars or forks of consequence.

## Where the nine agree

Mitose answers the cognitive-load objection by moving it. The person supplies intent; the agent is supposed to place requirements in Cell, Flow, and Tissue and to obey checkable rules — the seam sentence, no Tissue writes inside an instruction, live API resolution rather than memory. The old roadmap order is inverted. Agents are being asked to *build* Mitosis systems before Mitosis is a runtime that governs agents.

The document chain is read as the lineage thesis applied to construction: a requirement, a behaviour contract, and a program that must not pretend the earlier artefacts did not exist. What remains unproven is the same across the set. No stranger has run the pipeline, generated Demos are not shown under CI, and the distance from Demo to a deployable service is unaddressed. The bet is now partly on the agentic IDE ecosystem, not only on the framework’s technical merits.

## Where they diverge

The split is over how much weight to give an unvalidated front door.

| Reading | Models | Implied steady state |
|---|---|---|
| Bullish pivot | Dola, Qwen; OpenAI and Gemini in kind | Preferred substrate for AI-built, auditable systems in regulated work; the prompt-level pattern may outlive Dart. |
| Conditional upgrade | Kimi, GLM, DeepSeek | Reference architecture remains the base case; the agent-delivery path is now live, agent-governance is not. |
| Gated niche | Claude, Grok | A useful spec-driven toolkit if a non-author Demo survives tests; otherwise a documented stall. |

Dola and Qwen treat the pivot as a masterstroke toward an AI-native governance substrate. Qwen adds that the placement guides could travel as prompts beyond Dart. OpenAI recasts the project as an application compiler — intent, WalkThrough, governed runtime, and assessment as one lineage. Gemini reads Mitose as confirmation that the biomimetic strictness was always a surface for generated, non-entangling units in regulated systems.

Claude, Grok, and Kimi are tighter. Claude’s weights are a spec-driven niche toolkit (45%), a stall after the pipeline (30%), and production graduation (25%). Kimi lowers “respected reference architecture with an agentic front door” from 60% to 45% and raises a genuine AI repositioning from 25% to 40%, most of that a delivery system and only part true agent governance. Grok’s fork is method-becomes-product versus method-outruns-runtime, with three tests the repository cannot grade itself: a stranger’s BRD compiles without the author, a generated ledger snapshots and replays inside the causal model, and a fourth package ships once and stays.

GLM keeps the ledger runtime as the most likely outcome, upgrades the agent option, and marks generation-before-replay as the correction. DeepSeek names the sharpest failure: output that compiles but breaks provenance, validation, authority, or the pulse chain would discredit the thesis faster than slow adoption would.

## Composite judgment

The rc.5 thesis — a causally closed runtime for systems that must explain themselves — still stands, and is no longer the whole story. Mitosis is also trying to make construction accountable: the genome is copied by a gated process rather than by a compiler. That is a coherent second intent, and the only plausible answer on offer to the learning-cost problem. It does not yet move the project toward replay, distribution, or a second maintainer.

The shared near-term test is empirical, not rhetorical:

- stable 1.0 with a frozen API;
- a Mitose run on a requirement the author did not write;
- generated code checked for the causal contract, not merely for a green analyzer;
- either a Flutter binding or an explicit backend-first claim.

Until one of those appears, the disciplined summary is the distinction the nine reach by different routes: agents now help build Mitosis; the larger bet would be Mitosis helping to govern agents. The pipeline makes the first clause true on paper. It has not made the second clause true at all.
